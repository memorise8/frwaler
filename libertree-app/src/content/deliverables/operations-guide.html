1. 개요 (시스템 구성 요약)

libertree는 클라이언트가 제공한 scroll_index.xlsx의 글로벌 정부·연구·학술 사이트 (1,994 entries / 고유 host 832~833)에서 메타데이터 + PDF 원문 + 추출 텍스트 + (선택)한국어 요약을 자동 수집·저장·조회하는 시스템입니다.

1.1 구성 요소

구성 요소기술포트역할
크롤러Python 3.12 (crawler/ 패키지)-수집·다운로드·텍스트추출·요약 CLI 및 운영 스크립트
관리자앱 finolawNext.js 163001대시보드·검색·수집현황·요약검토·크롤러 관리 UI (Basic Auth)
열람앱 libertree-appNext.js 16컨테이너 3001 → 호스트 루프백 3101(기본), 로컬 dev 3000열람 전용 카탈로그(읽기 전용, 하드닝 컨테이너)
DBSQLite (WAL 모드)-data/libertree.db (약 5.2GB)
Blob 저장소로컬 디스크-libertree/AAAA/BBBB/NNNNNNNNNNNN.{pdf,txt} (약 1.6~1.7TB)
포트 주의: finolaw는 package.json에서 next dev/start -p 3001로 고정되어 있고, 루트 docker-compose.yml이 3001:3001로 노출합니다. libertree-app은 next dev 기본 포트가 3000이며, Docker 배포 시에는 컨테이너 내부 3001을 호스트 루프백 127.0.0.1:3101(기본, LIBERTREE_HOST_PORT로 변경)로만 노출합니다. (libertree-app/RUNTIME.md, libertree-app/docker-compose.yml 확인)

1.2 두 개의 웹앱 차이 (중요)

  • finolaw — 완전한 관리자앱. 검색·대시보드 외에 /admin/status, /admin/collection-report, /admin/summary, 그리고 크롤러 실행 라우트(/crawler, /auto-add, /smart-find)까지 포함합니다.
  • libertree-app — 열람 전용 카탈로그. RUNTIME.md 기준으로 애플리케이션 라우트는 /, /search, /search/:id, /api/blob/:seq_id/:ext, /api/health 뿐이며, 크롤러/관리자 라우트 (/admin, /api/crawler, /auto-add, /smart-find 등)는 의도적으로 제거되어 인증 후 404를 반환합니다. 읽기 전용 컨테이너로 실행됩니다.

1.3 DB 경로에 관한 실제 상태 (운영자 필독)

저장소에는 SQLite 파일이 두 개 존재합니다. 운영자는 반드시 구분해야 합니다.

  • data/libertree.db → ../libertree-app/data/libertree.db 심링크 (현재 운영 정본 DB, 약 5.2GB). 운영 스크립트(recover_pdfs.py, backfill_text_extraction.py, bulk_summarize_gemma.py)는 모두 이 경로를 기본값으로 사용합니다.
  • data/papers.db (약 459MB) — 레거시 경로. crawler/main.py의 상수 DB_PATH = data/papers.db와 finolaw/README.md가 이 파일을 가리킵니다.
⚠️ 불일치 주의: python -m crawler.main <명령>은 코드상 기본 DB로 data/papers.db를 사용하도록 하드코딩되어 있습니다(crawler/main.py:12). 반면 대규모 수집/요약/텍스트추출 운영 스크립트와 현재 정본 데이터는 data/libertree.db에 있습니다. 크롤러 CLI를 정본 DB에 대해 실행하려면 배포 환경에서 두 경로가 동일 파일을 가리키도록 맞추거나(심링크/볼륨 매핑), 스크립트/컨테이너 설정을 확인해야 합니다. CLI 사용 전 어떤 DB 파일이 대상인지 반드시 확인하십시오.

3. 배포 & 기동

3.1 관리자앱 finolaw — 루트 docker-compose.yml

메인 배포 스택. 단일 app 컨테이너(Next.js 포트 3001 + Python/Playwright 런타임).

cd /data_raid/ruci_workspace/frwaler_job
cp .env.example .env                    # ADMIN_USER/ADMIN_PASSWORD 편집
cp crawler/.env.example crawler/.env    # OPENAI_API_KEY 등 편집
docker compose up -d                    # 이미지 crawler-poc:mvp 기동

컨테이너 정의 (docker-compose.yml 실제 값):

  • 이미지 crawler-poc:mvp, 컨테이너명 crawler-poc, 포트 3001:3001
  • env_file: .env, crawler/.env
  • 볼륨: ./data:/app/data(rw), ./libertree:/app/libertree:ro(읽기전용), ./.cache:/app/.cache, ./crawler/sites/custom, ./crawler/sites/configs
  • restart: unless-stopped (서버 재부팅 시 자동 복구. 단 docker compose stop으로 명시적으로 끈 상태는 유지)
  • Healthcheck: http://localhost:3001/에 대해 HTTP 200/401이면 정상(인증 뒤라 401도 healthy)

끄기/켜기 (프로젝트 루트에서):

docker compose stop      # 끄기 (컨테이너 유지, 데이터 보존)
docker compose start     # 다시 켜기
docker compose down      # 컨테이너 제거 (이미지·볼륨 유지)
docker compose up -d     # 재기동 (crawler-poc:mvp 재사용)

DB·blob은 호스트 디렉토리(./data, ./libertree)에 있어 컨테이너를 껐다 켜도/제거해도 데이터는 안전합니다.

접속: http://<서버IP>:3001 — Basic Auth 자격증명은 루트 .env의 ADMIN_USER/ADMIN_PASSWORD.

3.2 열람앱 libertree-app — libertree-app/docker-compose.yml

읽기 전용·하드닝된 카탈로그 전용 스택. finolaw의 포트 3001 소유권을 건드리지 않도록 루프백에만 노출.

cd /data_raid/ruci_workspace/frwaler_job/libertree-app
export LIBERTREE_HOST_APP_DATA_ROOT=/data_raid/ruci_workspace/frwaler_job/libertree-app/data
export LIBERTREE_HOST_BLOB_ROOT=/data_raid/ruci_workspace/frwaler_job/libertree
export ADMIN_USER=admin ADMIN_PASSWORD='...'
docker compose -f docker-compose.yml build
docker compose -f docker-compose.yml up -d
curl --fail --user "$ADMIN_USER:$ADMIN_PASSWORD" http://127.0.0.1:3101/api/health
docker compose -f docker-compose.yml down

하드닝 특성 (docker-compose.yml 실제 값): read_only: true, cap_drop: [ALL], no-new-privileges:true, tmpfs /tmp(64m), pids_limit: 128, restart: "no", 모든 바인드 마운트 read_only. 노출은 127.0.0.1:${LIBERTREE_HOST_PORT:-3101}:3001.

/api/health: Basic Auth + 카탈로그 read-only 연결로 최소 쿼리를 수행하는 준비성(readiness) 프로브. 정상=200, 자격증명 오류=401, 카탈로그 접근 불가/오설정=503.

libertree-app/에는 과거 이력용 compose 변형 파일이 함께 존재합니다: docker-compose.port-3001.yml, docker-compose.port-3001.pre-mvp-ui.yml, docker-compose.port-3001.pre-taxonomy.yml, docker-compose.port-3001.pre-medium-taxonomy.yml. 현재 운영 기준 파일은 docker-compose.yml입니다.

3.3 로컬(비-Docker) 실행

# finolaw (포트 3001 고정)
cd finolaw && npm install && npm run build && npm run start

# libertree-app (dev 기본 3000)
cd libertree-app && npm install && npm run dev

4. 크롤러 운영 (CLI)

진입점: python -m crawler.main <subcommand> (crawler/main.py). .venv/bin/python으로 실행 권장.

4.1 실제 서브커맨드 목록 (argparse에서 확인)

서브커맨드역할
crawl특정 사이트 수집 (메타데이터 → documents 테이블)
scan-index목록 API만 스캔해 doc_index 갱신 (상세 미조회) — scan_index 지원 크롤러만
list-sites등록된 사이트·문서수 목록
stats사이트별 문서수 + 다운로드 상태 집계
test-config생성된 크롤러 config 테스트
download첨부파일(PDF/HWP/HWPX) 다운로드 → 12자리 blob 레이아웃
convert다운로드 파일(HWP/PDF)을 마크다운/텍스트로 변환
summarize요약 없는 문서에 한국어 요약 생성
smart-find임의 URL에서 다운로드 가능 문서 탐지 (NDJSON 출력)
auto-addGPT 에이전트가 URL 분석 → GenericCrawler JSON config 자동 생성 (NDJSON)
auto-add-codexTier 2: Codex CLI로 커스텀 크롤러 자동 생성 (NDJSON)

4.2 명령별 실제 플래그

crawl <site_id>

--limit N            저장할 최대 문서 수
--search TEXT        키워드 검색 필터
--doc-type CODE      문서유형 코드 (예: 001_02)
--date-from YYYY-MM-DD / --date-to YYYY-MM-DD   날짜 필터
--incremental        DB에 없는 신규 문서만 수집 (증분)
--gap-fill           결손 DOC_ID만 스캔·수집 (지원 크롤러만)

(사이트가 해당 파라미터를 지원할 때만 전달됨. mohw는 delay 2.5초, 그 외 1.0초.)

download [site_id] — site_id는 선택(생략 시 전체)

--limit N     다운로드 최대 건수
--retry       이전에 실패(download_status='failed')한 것만 재시도

파일명은 항상 {12자리 ID}.pdf(또는 .hwp/.hwpx), 경로는 libertree/AAAA/BBBB/AAAABBBBCCCC.ext. 원본 파일명은 documents.original_filename에 보존. curl -sL --max-time 30으로 .tmp에 스테이징 후 원자적 교체(부분 전송 방지). 확장자는 URL 힌트 우선, 없으면 매직바이트 감지.

convert [site_id]

--limit N     변환 최대 건수

summarize [site_id] — site_id는 선택(생략 시 전체)

--limit N                     이번 실행 최대 처리 행수
--provider gpt|openai|gemini|google   프로바이더 오버라이드 (기본 $LLM_PROVIDER 또는 'gpt')
--doc-id N                    단일 문서 재요약 (UI '재요약' 버튼용)

요약 소스 우선순위: abstract → 디스크의 txt_path 텍스트 → title.

scan-index <site_id>

--doc-type CODE       문서유형 필터
--no-mark-deleted     미발견 행을 삭제 표시하지 않음(부분 스캔용)

test-config <site_id> --limit N(기본 3)

smart-find <url>

--max-pages N   목록 페이지 최대 스캔 (기본 20)
--max-depth N   상세 링크 추적 깊이 (기본 3)
--delay FLOAT   요청 간 지연초 (기본 1.0)
--provider gpt|gemini   AI 폴백 프로바이더
--no-ai         LLM 폴백 비활성
--save-db       발견 문서를 DB(papers 테이블)에 저장

auto-add <url>

--site-id ID          자동 생성 site_id 오버라이드
--browser             SPA용 헤드리스 브라우저 강제
--dry-run             OpenAI 호출 없이 예정 작업만 출력
--max-iterations N    에이전트 반복 상한 (기본 15, 복잡 사이트는 30 등)

auto-add-codex <url>

--site-id ID / --site-name NAME
--timeout-seconds N   (기본 1200)

4.3 사이트 추가 방법

docs/HANDOFF.md 기준 크롤러 정의는 두 가지 형태:

  • 선언형(declarative): crawler/sites/configs/*.json — GenericCrawler가 실행. auto-add가 생성.
  • 커스텀: crawler/sites/custom/*.py — BaseCrawler(crawler/base_crawler.py) 상속. AI가 생성 (auto-add-codex, 또는 scripts/claude_required_runner.py).

추가 흐름 예:

# 1) 자동 config 생성 (GPT)
.venv/bin/python -m crawler.main auto-add "https://example.gov/board" --site-id example-gov
# 2) 테스트
.venv/bin/python -m crawler.main test-config example-gov --limit 3
# 3) 실제 수집 → 다운로드 → 변환 → 요약
.venv/bin/python -m crawler.main crawl example-gov
.venv/bin/python -m crawler.main download example-gov
.venv/bin/python -m crawler.main convert example-gov
.venv/bin/python -m crawler.main summarize example-gov

자동 생성이 어려운 사이트는 auto-add-codex(Tier 2) 또는 수동 커스텀 크롤러 제작이 필요합니다.

4.4 정기 배치 체인 (scripts/cron_crawl.sh)

야간 배치 스크립트. 등록된 전 사이트에 대해 crawl(--incremental)→download→convert→summarize→stats 순으로 실행.

bash scripts/cron_crawl.sh once                  # 1회 실행 후 종료
SITES="ntrs mohw" bash scripts/cron_crawl.sh once  # 특정 사이트만

6. 저장소 구조 & 백업

6.1 SQLite (WAL)

  • 정본 DB: data/libertree.db (→ libertree-app/data/libertree.db), 약 5.2GB, WAL 모드.
  • WAL 덕분에 수집(쓰기)과 웹앱 조회(읽기)가 충돌 없이 동시 동작 → 웹앱은 자동 최신화.
  • 열람 컨테이너는 DB 파일 하나가 아니라 디렉토리 전체를 read-only 마운트해야 합니다(라이브 -wal/-shm 사이드카를 보아야 정상 조회. RUNTIME.md 참조).

6.2 Blob 트리 (12자리 폴더 규칙)

  • 경로 규칙: libertree/{seq[:4]}/{seq[4:8]}/{seq:012d}.{pdf|txt} — 12자리 zero-padded seq_id를 4-4-4 분할. 유틸: crawler/blob_storage.py, TS는 finolaw/src/lib/db.ts blobPath().
  • 예: seq_id 1 → libertree/0000/0000/000000000001.pdf (+ .txt 추출본).
  • 규모 약 1.6~1.7TB.

6.3 백업 권장

  • DB: 백업 전 WAL 체크포인트 후 스냅샷. 예: .venv/bin/python -c "import sqlite3; sqlite3.connect('data/libertree.db').execute('PRAGMA wal_checkpoint(TRUNCATE)')" 후 libertree.db(+-wal/-shm) 복사.
  • Blob: libertree/ 전체를 tar/rsync로 복사. docker-compose.yml 헤더 주석대로 바인드 마운트라 docker compose down 후에도 호스트에 남아 백업 용이.
  • 무결성: docs/HANDOFF.md의 납품 절차 — 수집 완료 → WAL 체크포인트 → 스냅샷 확정 → sha256 manifest 생성 → 외장 디스크 rsync 복사·검증. (납품 방식: 외장 디스크 2TB+ 물리 전달)
  • 감사/로그/보고 산출물은 대부분 data/audit/(로그는 data/audit/logs/)에 있으므로 함께 백업.

9.2 저장 경로 규칙은 계약과 동일

계약은 첨부/텍스트를 data/AAAA/BBBB/(레코드 sequence 12자리 기반, 1만 건 단위 하위 폴더) 구조로 저장하도록 규정했고(예: data/0000/0000/000000000001.pdf, .txt), 현재 운영도 동일한 4-4-4/12자리 규칙을 씁니다. 차이는 루트 폴더명뿐입니다:

  • 계약 문서: 루트 data/
  • 현재 운영: 루트 libertree/ (libertree/0000/0000/000000000001.pdf)

즉 S3 대신 로컬 디스크를 쓰되, 계약이 정한 "sequence 기반 계층형 폴더" 규칙은 그대로 준수합니다. 계약이 명시한 "로컬 파일 저장 구조(data/AAAA/BBBB/)와 동일하게 적용"을 로컬에서 충족합니다. (계약상 data/는 저장소에서 레거시 경로로 일부 잔존 — §1.3 참고.)

9.3 운영자가 알아야 할 함의

  • 확장/이중화 없음: RDS/S3/ECS의 관리형 백업·다중AZ·오토스케일이 없으므로, 백업(§6.3)과 서버 물리 가용성이 운영자 책임입니다.
  • DB 동시성: PostgreSQL이 아닌 SQLite이므로 다중 쓰기 프로세스를 동시에 돌리지 마십시오. 쓰기는 promote/runner/recover/backfill 계열로 한정하고, 웹앱·열람앱은 read-only로 접근합니다(WAL).
  • 납품 방식: 클라우드 배포가 아니라 외장 디스크 물리 전달(DB 5.2GB + blob 1.7TB + finolaw/compose/ Dockerfile + crawler/scripts + 문서 + sha256 manifest)로 진행합니다(docs/HANDOFF.md §10).

10. 저장소에서 확인 불가 / 유의 항목

  • 크롤러 CLI 기본 DB 경로 불일치: crawler/main.py는 data/papers.db를 기본 DB로 사용하나, 운영 스크립트·정본 데이터는 data/libertree.db. 배포 시 경로 정합성 확인 필요(§1.3).
