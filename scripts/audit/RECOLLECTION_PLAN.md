# 실제 재수집 착수 준비 계획 (2026-08-03)

케파 산정 확정(**1,980만건 / 72TB 하한**, `capacity_final_report.xlsx`) 이후, 실제 전량 재수집을 위한 준비 계획.
방침: 무조건 다 받음(DOAJ 포함). 천천히 제대로 — 안전·재개가능·검증 우선.

## 선결 3요소 진단 결과

### 1. 스토리지 ✅ 해결가능
- `/data_raid` (로컬 RAID): 3.6TB 여유뿐 → 72TB 불가.
- **`/data_raid/share/gdrive` = 1.0PB rclone(Google Drive) 마운트, 현재 0 사용** → 72TB 충분히 수용.
- 크롤러는 `LIBERTREE_BLOB_ROOT` env로 저장루트 지정(`crawler/blob_storage.py:25`). → gdrive 하위로 지정하면 됨.
- ⚠️ 검증필요: rclone→GDrive **쓰기 처리량**, Google **API 쿼터/일일한도**, 대용량 지속쓰기 안정성.

### 2. 크롤러 캡 3종 — 구조 파악 완료
| 캡 | 위치 | 현재값 | 실제수집 병목? |
|---|---|---|---|
| `limit` | 러너가 `crawl(limit=)` 주입 (main.py:270). **기본 None(무제한)** | 실제 수집은 `--limit 500`로 돌림 | ✅ 대부분 500서 멈춤. `--limit` 안주면 해제 |
| `_MAX_PAGES` | 각 크롤러 모듈상수 (예 doaj:30, amu-hal:32) | 200 | ✅ 페이지당 20~50건 → 크롤러당 4천~1만 천장. **대형 치명적** |
| `max_wall` | 각 `crawl()` 함수내 지역변수 | 25*60초 | ✅ 대형에서 조기중단 |
- 캡을 개별 편집(~600파일)하지 말고 **env 오버라이드**로 일괄 해제 권장: `LIBERTREE_MAX_PAGES`, `LIBERTREE_MAX_WALL_S`. count-only 하네스가 이미 정규식으로 무력화한 전례 있음 → 영구 env화가 깨끗.

### 3. 재개/중복방지 — 확인필요
- seq_id 기반 blob 레이아웃. 이미수집분(525,570) skip 여부, 재실행시 중복저장 안 하는지 검증.

## 단계별 실행 계획

**Phase 0 — 준비·검증 (무저장/소량, 안전)** ← 지금 여기
- (a) gdrive 쓰기검증: 보류(저장타깃 = 로컬디스크 추가확보로 결정). 하드웨어 준비되면 신규디스크에 처리량 검증.
- (b) 캡 env화: `LIBERTREE_MAX_PAGES`/`LIBERTREE_MAX_WALL_S` 오버라이드 추가 + 러너 `--limit` 무제한. 크롤러 1개로 회귀검증. ← 다음
- (c) DOAJ 실체검증: ✅ **완료 (2026-08-03)** — 아래 결과. **51TB → ~5~9TB로 대폭 하향.**
- (d) 재개검증: 이미수집 사이트 재실행 → 중복 없이 skip 되는지 확인. ← 남음

### (c) DOAJ 실체검증 결과 ★핵심 보정
라이브 API 다중샘플(400+200건, 저널 90+개 다양성) 실측:
- 크롤러는 crawl()에서 **PDF를 즉시 안 받음** — 메타+`pdf_url`만 저장(PDF는 별도 `download` 단계).
- `pdf_url`은 **`.pdf` 명시링크만** 채택. 직접 PDF 보유율 = **저널편중에 따라 0~18%, 다양성샘플 12~18%**. → 직접PDF ~130만~230만건.
- 저장필터(title+abstract≥100) 통과 **77~90%** → 메타 저장가능 ~1,000만~1,200만건.
- 링크된 PDF는 실제 해석됨(12/12 HTTP200 application/pdf).
- **결론: DOAJ 직접다운로드 PDF ≈ 5~9TB (기존 51TB ❌). + 메타 ~1,000만건(텍스트, 수십GB).**
- ⚠️ 한계: 크롤러가 랜딩페이지를 안 따라감 → 실제 PDF 존재율은 더 높을 수 있으나 현 크롤러 기준 상기 수치.

### 케파 보정 (PDF 용량 기준)
- 기존: 19.8M / **72TB** (DOAJ 13.36M×3.83MB=51TB 가정).
- 보정: DOAJ PDF ≈ 8TB, non-DOAJ 6.44M×3.83MB ≈ 24TB → **실제 PDF 총량 ≈ 30~32TB** (레코드수 케파 ~18M은 유지, 저장은 절반).
- ⇒ 로컬디스크 확보 목표: **~35TB(여유 포함)**면 전량 가능. 72TB 불필요.

**Phase 1 — 중형·다양성 우선 (non-DOAJ ≈ 6.4M / 21TB)**
- HAL 기관포털·DSpace 리포지토리·정부 오픈데이터(CKAN) 등 ~800사이트. 건당 가치 높음, 관리 용이.
- 대형순 배치, 캡해제 상태로 병렬 수집. 사이트별 진행/성공률 모니터.

**Phase 2 — DOAJ 메가 (13.36M / 51TB, 전체의 67%)**
- 별도 단계. Phase0(c) 실체검증 통과 후. rclone 처리량·쿼터 관리하며 장기 수집.
