# 요구사항 분석서 — livertree

## 1. 프로젝트 배경

이용자 (Libertree, `tree@libertree.co.kr`) 는 약 1,500개 한국 행정·법률
관련 웹페이지에 흩어져 있는 게시글과 첨부 문서 (PDF / HWP / HWPX 등) 를
주기적으로 수집·텍스트화·AI 요약하여 검색 가능한 단일 데이터베이스로
관리할 필요가 있다. 현재는 사이트별로 사람이 수동 수집·보관하고 있어 (a)
누락 발생, (b) 동일 자료의 중복 수집, (c) 검색·요약 부재로 인한 실무 활용
어려움 같은 문제가 있다.

## 2. 시스템 목표

| ID | 목표 |
|---|---|
| G-1 | 사이트 무관 통합 시퀀스로 모든 문서를 식별 (1조 한도) |
| G-2 | 메타정보 + 첨부파일을 함께 수집하여 한 행에 묶음 |
| G-3 | 첨부파일 형식 (PDF/HWP/HWPX) 자동 인식 후 텍스트 추출 |
| G-4 | OpenAI / Gemini 기반 한국어 요약 자동 생성 |
| G-5 | 관리자가 수집 진척을 한눈에 보고, 필요 시 단건 재요약 가능 |
| G-6 | 운영 환경에서 재현 가능한 컨테이너 배포 |

| FR-15 | 단일 명령 컨테이너 배포 | `docker compose up -d` | ✅ |

## 4. 비기능 요구사항

| ID | 요구사항 | 충족 방법 |
|---|---|---|
| NFR-1 | 1조 (10¹²) 도큐먼트까지 파일시스템 친화적 분산 | 3-level 12자리 계층 (`data/AAAA/BBBB/N.ext`) |
| NFR-2 | 단일 writer / 다중 read 동시 안전성 | SQLite WAL 모드 |
| NFR-3 | LLM 요약 호출 멱등성 | `documents.summary` COALESCE-on-NULL update |
| NFR-4 | 추적 가능한 회귀 검증 | unittest 26+ 케이스 + Codex 10 라운드 리뷰 |
| NFR-5 | 한국어/CJK 검색 정확도 | trigram tokenizer + LIKE 폴백 |
| NFR-6 | 운영 디스크 절약 | 파일 + 추출 텍스트 동일 base 이름 재사용, .bin 폴백으로 잘못된 확장자 방지 |
| NFR-7 | 키 안전성 | 환경 변수 분리 (`.env`, `crawler/.env` — 빌드 컨텍스트 제외) |

## 5. 데이터 요구사항

`documents` 테이블 17 + 3 컬럼:

| 그룹 | 컬럼 |
|---|---|
| 관리 | `id` (INTEGER PK AUTOINC), `crawled_at` |
| 사이트/식별 | `site_id`, `external_id`, `meta_url` |
| 본문 | `title`, `published_date`, `posted_date`, `authors` (`;`), `publisher` (`;`), `journal`, `pdf_url`, `keywords` (`,`), `abstract` |
| 파일/처리 | `original_filename`, `pdf_path`, `txt_path`, `download_status`, `summary`, `metadata` (JSON) |

UNIQUE: `(site_id, external_id)`. 인덱스 4종 + FTS5 (trigram).

## 6. 사용자 요구사항 매핑

| 사용자 요구 | 충족 |
|---|---|
| "사이트명 + 사이트URL 만 등록하면 자동 운영" | `sites` 테이블 + `auto-add` 명령 |
| "글번호 / 제목 / 작성일 / 게시일 / 저자 / 출판사 / 저널 / 첨부파일URL / 키워드 / 초록 / 원파일명" | documents 17 컬럼에 1:1 매핑 |
| "저자/출판사 다중값" | `;` 구분 문자열 |
| "키워드 다중값" | `,` 구분 문자열 |
| "AI 요약" | OpenAI/Gemini 기반 한국어 3-5문장 |
| "관리자가 수집/요약 현황 모니터링" | `/admin/status`, `/admin/summary` |
