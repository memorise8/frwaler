# 운영 매뉴얼 — livertree

## 1. 일상 점검 (Daily Ops)

| 시간 | 점검 항목 | 명령 / 위치 |
|---|---|---|
| 09:00 | 야간 배치 완료 여부 | `tail -50 logs/scheduler.log` 또는 `/admin/status` |
| 09:00 | 사이트별 진행률 | `/admin/status` 4 카운트 + 진행 bar |
| 09:30 | 신규 요약 생성 결과 | `/admin/summary?status=summarized` |
| 10:00 | 다운로드 실패 추적 | `python -m crawler.main stats` |

## 2. 사이트 추가 절차

```bash
# 1. URL 분석 → JSON config 자동 생성
docker compose exec app python -m crawler.main auto-add https://example.go.kr/board

# 2. config 검증
docker compose exec app python -m crawler.main test-config <site_id> --limit 3

# 3. 등록 후 첫 수집
docker compose exec app python -m crawler.main crawl <site_id> --limit 10

# 4. 다운로드 + 변환 + 요약
docker compose exec app python -m crawler.main download <site_id>
docker compose exec app python -m crawler.main convert <site_id>
docker compose exec app python -m crawler.main summarize <site_id>
```

## 3. 장애 대응

### 크롤 실패 (사이트별)

| 증상 | 원인 추정 | 조치 |
|---|---|---|
| HTTP 403 / 429 | 봇 차단 / 요청 폭주 | `--delay` 늘리기, playwright 모드 시도 |
| HTML 구조 변경 | 사이트 리뉴얼 | `auto-add` 재실행 → config 갱신 |
| 본문 비어있음 | JS 렌더링 누락 | `--browser` 옵션 |
| 게시글 누락 | gap 발생 | `scan-index <site>` + `--gap-fill` |

### 다운로드 실패

| 증상 | 조치 |
|---|---|
| 빈 파일 | `download <site> --retry` |
| HTML 응답 | URL 검증 (`pdf_url` 컬럼) |
| 네트워크 timeout | --max-time curl 옵션 조정 (`crawler/main.py` 내 30s) |

### 변환 실패

| 증상 | 조치 |
|---|---|
| `MISSING` | `pdf_path` 컬럼과 실제 파일 일치 확인. 재다운로드 |
| `FAILED extract` | 손상된 파일. 원본 URL 확인 후 재다운로드 |
| HWP 추출 0 byte | PrvText 스트림 없는 옛 버전. `--reextract` 시도 |

### 요약 실패

| 증상 | 조치 |
|---|---|
| 500 (재요약 버튼) | `OPENAI_API_KEY` 만료 / 한도 초과 → 키 갱신 |
| 너무 짧은 요약 | qa_summary_quality 결과 확인 후 SYSTEM_PROMPT 조정 |
| 너무 abstract 와 유사 | 입력 텍스트가 짧음. txt_path 파일로 입력 변경 |

## 4. 백업 / 복구

### 정기 백업 (일 1회 권장)

```bash
# 스케줄러 일시 정지 (선택)
docker compose exec app supervisorctl stop scheduler

# 핵심 자산 압축
TS=$(date +%Y%m%d-%H%M)
tar -C /path/to/livertree -czf "livertree-$TS.tgz" \
    data/papers.db data/AAAA crawler/sites/custom crawler/sites/configs

# 스케줄러 재개
docker compose exec app supervisorctl start scheduler
```

### 복구

```bash
docker compose down
tar -xzf livertree-YYYYMMDD-HHMM.tgz
docker compose up -d
```

DB만 복구 시 새 컨테이너에서 `migrate_livertree` + `migrate_documents_fts`
한 번만 더 실행 (idempotent).

## 5. 스케일링

| 시나리오 | 조치 |
|---|---|
| 디스크 60%+ | `LIVERTREE_DATA_ROOT` 를 더 큰 디스크로 이동 후 compose 재시작 |
| 단일 호스트 CPU 100% | playwright 동시성 줄이기 / cron_crawl.sh 사이트 분할 실행 |
| LLM 비용 증가 | provider GPT-4 mini → Gemini flash 전환 (`LLM_PROVIDER=gemini`) |
| 검색 응답 느림 | `documents_fts` ANALYZE 재실행, 인덱스 재구축 |

## 6. 보안 운영

| 항목 | 절차 |
|---|---|
| API 키 회전 | `crawler/.env` 갱신 → `docker compose restart app` |
| 어드민 비밀번호 | `.env` `ADMIN_BASIC_AUTH_*` 갱신 후 재시작 |
| 호스트 네트워크 | 3001 포트는 reverse proxy (Caddy/Traefik) 뒤에서만 노출 |
| 백업 파일 | 별도 호스트로 rsync, 7일 보관 |

## 7. 정기 작업 일정

| 주기 | 작업 |
|---|---|
| 매일 03:00 (자동) | scheduler 의 incremental crawl→download→convert→summarize |
| 매주 월 09:00 (수동) | qa_crawl_accuracy 보고서 (xlsx) 검토 |
| 매월 1일 | qa_summary_quality LLM judge 30 sample |
| 분기 1회 | playwright 브라우저 업데이트 (`docker compose build --no-cache`) |
| 반기 1회 | DB ANALYZE / VACUUM (서비스 시간 외 점검 창) |
