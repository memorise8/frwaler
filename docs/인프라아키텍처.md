```
┌────────────────────────────────────────────────────────────────┐

│  │  │ supervisord PID 1  │────│ [program:finolaw]       │   │   │
│  │  │                    │    │ npx next start :3001    │   │   │
```

## 2. 컴포넌트별 책임

| 컴포넌트 | 책임 | 비고 |
|---|---|---|
| supervisord | PID 1, 컨테이너 lifecycle | finolaw + scheduler 두 program 관리 |
| finolaw (Next.js) | 관리자 UI + Read API + Route Handler | 포트 3001 노출, better-sqlite3 read-only |
| scheduler (`cron_crawl.sh loop`) | 매일 03:00 KST 사이트 순회 배치 | crawl→download→convert→summarize |
| Python 크롤러 (on-demand) | `docker compose exec` 또는 finolaw API 가 spawn | sqlite WAL writer |
| SQLite (papers.db) | 단일 writer + 다중 reader | WAL 모드, 트리거로 FTS 동기화 |
| 12자리 파일 계층 | 1조 한도 안에서 분산 저장 | `data/AAAA/BBBB/N.{ext}` |

## 3. 데이터 흐름

### 3.1 수집 파이프라인

```
사이트 (HTTPS) ──┐
                ▼
      crawler.main crawl <site>
        - HTML 파싱 (bs4 / cloudscraper / playwright)
        - paper_dict 생성
                │
                ▼
      livertree_adapter.paper_to_document
        - JSON metadata 보존, category/doi promote
                │
                ▼
      db.upsert_document
        - documents INSERT or UPDATE
        - URL 변경 감지 → 디스크 cleanup_doc_files
        - summary/metadata COALESCE preserve
                │
   ┌────────────┼─────────────┐
   ▼            ▼             ▼
documents   documents_fts   sites.last_crawled
 (INSERT)   (트리거 동기화)
```

### 3.2 다운로드 → 변환 → 요약 → 검색

```
  documents.pdf_url
        │
        ▼
  cmd_download
   - .tmp 임시 → magic-byte sniffer
   - rename to data/AAAA/BBBB/N.{pdf|hwp|hwpx|bin}
   - update_document_paths(pdf_path, download_status='downloaded')
        │
        ▼
  cmd_convert
   - extract_text_{pdf|hwp|hwpx}
   - write data/AAAA/BBBB/N.txt
   - update_document_paths(txt_path)
        │
        ▼
  cmd_summarize
   - 입력: abstract → txt 파일 → title
   - summarizer.summarize_text(text, title, provider)
   - update_document_summary
        │
        ▼
  documents_fts (트리거 자동 동기화)
        │
        ▼
  finolaw /search FTS5 (trigram + LIKE 폴백)
```

## 4. 동시성 / 일관성 모델

| 영역 | 모델 |
|---|---|
| DB | SQLite WAL — 1 writer (크롤러 또는 스케줄러) + N readers (finolaw + ad-hoc) |
| 파일 저장소 | append-only 의미. 같은 doc_id 의 동일 ext 파일은 멱등 |
| URL 변경 시 | 트랜잭션 안에서 DB 컬럼 NULL + 디스크 unlink, 후속 download 가 새 콘텐츠로 재생성 |
| 트리거 | documents → documents_fts 동기화. 각 INSERT/UPDATE/DELETE 단일 트랜잭션 |
| LLM 요약 | 외부 API 호출이라 트랜잭션 외부. 호출 결과만 update_document_summary 로 반영 |

## 5. 확장 시나리오

### 5.1 단일 호스트 (현재)
- 컨테이너 1개, 디스크 50 GB+
- 1,500 사이트 × 평균 100 글 = 150,000 row 수준에서 충분
- 응답 속도: FTS 쿼리 < 50ms, 페이지 < 200ms

### 5.2 다중 호스트 (Phase 2 옵션)
- 크롤러 / 스케줄러 컨테이너 1대
- finolaw UI 컨테이너 N대 (read-only mount)
- DB 위치: NFS / EFS 공유
- 주의: SQLite WAL 은 NFS 에서 신뢰성 떨어짐 → PostgreSQL 마이그레이션 검토 시점

### 5.3 클라우드 (AWS 예시)
| 컴포넌트 | AWS 매핑 |
|---|---|
| app 컨테이너 | ECS Fargate task |
| 데이터 디렉터리 | EFS volume |
| 외부 노출 | ALB + ACM TLS |
| 모니터링 | CloudWatch log driver |

## 6. 모니터링 / 알람 (현재 + 권장)

| 신호 | 현재 | 권장 추가 |
|---|---|---|
| 컨테이너 헬스 | docker compose healthcheck | uptime monitor (Healthchecks.io 등) |
| 스케줄러 실패 | logs/scheduler.err | 실패 시 슬랙/이메일 알림 |
| LLM 비용 | 수동 OpenAI dashboard 확인 | 일일 비용 알람 (OpenAI usage API) |
| 디스크 사용 | 수동 `df -h` | Prometheus node_exporter |

## 7. 보안 경계

| 경계 | 통제 |
|---|---|
| 외부 → app | reverse proxy (HTTPS 종단) + Basic Auth (`/admin/*`) |
| app → DB | 컨테이너 내부, 외부 노출 없음 |
| app → LLM | 환경 변수 키, 로그에 키 남기지 않음 |
| Codex CLI 권한 | 컨테이너 내부 codex sandbox (워크스페이스 격리) |
| 백업 파일 | 별도 호스트로 rsync, 7일 보관 |

## 8. 비기능 지표 목표

| 항목 | 목표 |
|---|---|
| `/search` p95 응답 | < 300ms |
| `/api/admin/summarize` p95 | < 30s (LLM 포함) |
| 야간 배치 완료 | 03:00 ~ 05:00 KST 안에 5개 핵심 사이트 처리 |
| 다운로드 성공률 | ≥ 95% (정적 사이트), ≥ 80% (JS 렌더링) |
| 요약 휴리스틱 통과율 | ≥ 90% |
