# 개별 수집기 상태 조회 기능 검토 — 2026-09-11

**제작 가능하다.** 기존 납품 화면·작업 큐·로그·문서 조회 기능을 활용하면 된다. 현재 상태와 과거 검증을 정확히 구분하는 집계가 핵심이다. 이번 작업에서는 코드와 데이터 구조를 조사하고, 남은 수집기 10개를 재검사했으며, 최신 검사 근거를 검색하는 로컬 시제품을 만들었다. 운영 화면을 배포하거나 운영 수집을 시작하지는 않았다.

## 다른 수집기 검사

최대 3건·60초, 동시 2개 이하, 동일 호스트 동시 1개로 10개를 검사했다. 수정된 로컬 코드를 읽기 전용으로 연결한 임시 컨테이너와 출처별 임시 SQLite를 사용했다.

| 대상 | 결과 | 다음 확인 사항 |
|---|---|---|
| `ntrs`, `mohw` | 각각 3건 저장 | 현재 검사는 표본 수준 |
| `nhc-gov-cn`, `en-nhc-gov-cn` | HTTP 502, 저장 없음 | 원격 응답·현재 주소 확인 |
| `research-collection-ethz-ch-search` | JSON 응답 해석 실패 로그, 저장 없음 | 실제 응답 내용 및 API 변경 여부 |
| `ir-lib-uth-gr-xmlui` | curl exit 35, 저장 없음 | TLS 연결 및 서버 응답 |
| `drugsandalcohol-ie-cgi` | 요청 재시도 후 실패, 저장 없음 | HTTP 응답·접속 경로 |
| `bfe-admin-ch-bfe`, `repositorio-uchile-cl-discover`, `motir-go-kr-kor` | 0건 종료 | 실제 빈 목록인지 주소·선택자 변경인지 구분 |

이들 대부분은 실패를 출력하고 정상 반환하므로, 작업 상태 `done`만 보면 건강한 수집기로 오인할 수 있다. 이번에 정상 판정하지 않은 8개는 다음 진단 대상으로 남긴다.

전체 등록 1,243개 식별자의 **과거 검사와 후속 재검사 중 최신 기록**을 합치면 표본 저장 확인 786, 일부 저장 후 중단 27, 시간 내 미확인 75, 차단 신호 43, 0건 원인 미확인 308, HTTP 오류 2, 원문 검사 제한 2다. 서로 다른 코드 버전·제한 조건의 검사 기록을 합친 값이며, 현재 코드 전체를 재검증한 정상률이 아니다. 같은 출처에 여러 식별자가 있을 수 있다. 등록에서 빠진 `scienceon-api`와 18개 중복 식별자는 별도 관리가 필요하다.

## 재사용할 기능과 부족한 부분

현재 `libertree` 브랜치:

- `delivery/fe/src/lib/crawler-health.ts`: `AUDIT_DATE = 2026-08-06`, CSV를 읽는 정적 정상/실패 분류.
- 개별 화면과 실행 버튼은 있으나, 실행 등록 이후 상태 추적은 연결되지 않았다.
- `crawl_jobs`에는 대기·실행·완료·실패, 시작/종료 시각, 신규 저장 건수, 오류가 있다. 현재 워커의 저장 건수는 실행 전후 전체 문서 수 차이다.

별도 `origin/delivery-mvp-audit-20260812` (`6d95489`)의 구현:

- 작업 목록·상세·로그·취소·재시도·스케줄·lease 및 정지 작업 복구.
- `/sites/verification`, `/freshness`, `/documents`와 수집기별 문서 조회 화면.
- 과거 검사 결과와 해당 설치 환경에서의 실행 결과를 따로 보여주는 구조.
- **보완 필요:** `resolveVerificationState()`가 `best_saved_count > 0`을 최신 실패보다 먼저 처리한다. 예전에 성공하고 방금 실패한 수집기가 계속 ‘여기서 수집 확인’으로 표시될 수 있다. 과거 성공 이력과 최근 결과를 별도 필드로 표시해야 한다.

두 브랜치의 구현 수준이 다르므로 납품 브랜치의 운영 화면을 기반으로 확장하는 편이 적합하다. 현황 조회 코드만 현재 사이트에 연결하는 경우에도 실제 실행을 관리하는 동일 BE를 사용해야 한다. 운영 컨테이너의 실제 버전과 데이터 연결은 구현·배포 시 다시 확인해야 한다.

## 권장 화면

한 목록에서 수집기 ID·기관·국가·문서 유형을 검색하고, 아래 두 상태를 별도로 필터링한다.

| 구분 | 표시값 |
|---|---|
| 작업 진행 상태 | 실행 기록 없음 / 대기 / 실행 중 / 중지 요청 / 종료 / 실패 / 취소 |
| 최근 검사 결과 | 표본 저장 확인 / 일부 저장·중단 / 0건 원인 미확인 / 차단 / 시간 초과 / HTTP 오류 / 코드 오류 / 미검증 |

개별 상세에는 마지막 실행·마지막 성공·확인 시각, 최신 오류와 로그, 신규/갱신/중복 문서 수, 최근 문서 제목·링크, 실행 코드 버전·환경을 보여준다. ‘신규 문서 없음’은 목록 요청 성공과 기존 자료 확인 등 근거가 있을 때만 표시한다. DB 조회 불가는 0건과 구분한다. 예전에 저장된 문서가 있다는 사실만으로 현재 정상이라고 판정하지 않는다.

운영 API는 수집기별 최근 실행, 마지막 성공, 진행 중 작업을 함께 반환한다. 최신 실패가 과거 성공보다 우선 보이되 마지막 성공 이력은 남긴다. 실행 중 상태의 신뢰도를 위해 lease/heartbeat를 확인하고, 중간 오류를 내부에서 삼키는 수집기는 구조화된 수집 결과와 관측 로그를 함께 기록해야 한다. 저장 건수도 가능하면 실행별 실제 저장 이벤트로 계산해 같은 사이트의 동시 작업과 중복 문서를 구분한다.
