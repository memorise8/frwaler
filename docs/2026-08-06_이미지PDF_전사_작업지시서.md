# 이미지 PDF 전사 작업 지시서 (GPT 활용)

작성일 2026-08-06 · 대상 **16건 / 115쪽** · 예상 소요 **1순위 12건 약 4~5시간**

---

## 1. 무슨 일인가요

아래 자료들은 **글자를 복사할 수 없는 그림(스캔) PDF**입니다. 눈으로는 읽히지만 컴퓨터는 못 읽습니다.

- **1순위 12건** — 한국공인회계사회 `월간공인회계사` **2022~2025년 최신 실무자료**. 대체 자료가 전혀 없어 이걸 안 하면 통째로 못 씁니다
- **2순위 4건** — 한국회계기준원 자료. 같은 내용의 다른 파일이 이미 확보돼 있어 여유될 때만

GPT에 PDF를 올려 글자를 읽어내고(1차), **다른 대화창에서 원본과 대조 검수**(2차)하는 방식입니다.

> ⚠️ **왜 2번 하나요?**
> 기계는 `K-IFRS 1115`를 `K-IERS 1115`로 잘못 읽습니다. 실제로 시험해봤을 때 나온 오류입니다.
> 기준서 번호가 틀리면 답변 근거가 통째로 틀어지기 때문에, 만든 쪽과 검수하는 쪽을 분리합니다.

## 2. 폴더 구성

```
handoff_ocr_20260806/
├── 작업지시서_OCR.md          ← 지금 보는 문서
├── 작업목록_OCR.csv           ← 엑셀로 열어 체크하며 진행
├── 원본PDF/                   ← GPT에 올릴 PDF 16개
├── 프롬프트/                  ← 문서마다 하나씩, 내용이 미리 채워져 있음
│   ├── 01_14410.txt
│   └── ...
├── 프롬프트_2차검증_공통.txt   ← 검수용 (16건 공통, 하나만 씀)
└── 결과/                      ← 완성본을 여기에 저장
```

## 3. 작업 순서 (문서 1건 기준)

CSV에서 한 줄을 고른 뒤, 그 줄의 `PDF파일`·`프롬프트파일`·`저장할결과파일` 이름을 확인하세요.

### 1차 — 전사

1. GPT에서 **새 대화**를 엽니다 ← 문서마다 반드시 새 대화
2. `원본PDF/` 에서 해당 PDF를 **업로드**합니다
3. `프롬프트/` 에서 같은 번호의 `.txt`를 열어 **전체 복사 → 붙여넣기**
4. 결과 전체를 복사해 둡니다

### 2차 — 검수

6. **또 다른 새 대화**를 엽니다 ← 1차와 같은 대화에서 하면 안 됩니다
7. 같은 PDF를 다시 업로드합니다
8. `프롬프트_2차검증_공통.txt` 를 붙여넣습니다
9. 이어서 1차 결과 전체를 붙여넣습니다
10. 검수 결과의 **`수정 반영본`** 부분을 사용합니다

### 저장

11. `결과/` 폴더에 저장합니다. **파일 이름 앞의 번호만 그대로 두면 됩니다.**

    ```
    01_14410.md      ← CSV의 `저장할결과파일` 이름 그대로 (권장)
    01_14410.docx    ← 워드로 저장해도 됩니다
    01_14410_대리인의수익인식.txt   ← 뒤에 설명을 붙여도 됩니다
    ```

    - 형식은 **`.md` / `.txt` / `.docx` 아무거나** 편한 것으로 하세요
    - 앞의 `01_14410` 두 숫자만 유지되면 시스템이 알아서 찾아갑니다
    - 서식(굵게·표·제목)은 신경 쓰지 않으셔도 됩니다

12. CSV `완료` 열에 `O` 표시

## 4. 이런 경우엔 이렇게 해주세요

| 상황 | 조치 |
|---|---|
| GPT가 "읽을 수 없다"고 함 | PDF를 이미지(PNG)로 변환해 올려보세요. 그래도 안 되면 CSV `메모`에 "GPT판독불가" |
| 결과에 `[?판독불가]`가 많음 | 정상입니다. 지우지 말고 그대로 두세요. 나중에 사람이 확인할 표시입니다 |
| 2차 검수가 "재전사필요"로 나옴 | 1차부터 다시 (새 대화에서) |
| 문장이 뒤죽박죽 | 좌우 2단 편집 문서입니다. 1차 프롬프트 끝에 "이 문서는 2단 편집이다. 왼쪽 단을 끝까지 읽은 뒤 오른쪽 단으로 넘어가라" 한 줄 추가해 다시 요청 |
| 쪽수가 많아 GPT가 중간에 끊음 | "이어서 계속" 이라고 요청. 이어붙여 하나의 파일로 저장 |
| 표가 깨져 나옴 | "표는 마크다운 표로 다시 출력해줘" 요청 |

## 5. 하지 말아야 할 것

- ❌ **1차와 2차를 같은 대화에서 하기** — 자기가 쓴 걸 자기가 검사하면 오류를 그냥 넘깁니다. 이게 이 작업의 핵심입니다
- ❌ **파일 이름 앞 번호 바꾸기** — 어느 자료인지 못 찾습니다
- ❌ **한 대화에서 여러 문서 처리** — 앞 문서 내용이 섞여 들어갑니다
- ❌ **`[?판독불가]` 표시 지우기** — 불확실한 곳을 표시해 둬야 나중에 사람이 봅니다
- ❌ **읽기 어렵다고 GPT에게 "적당히 채워줘" 요청** — 그럴듯한 거짓 문장이 만들어집니다. 이게 제일 위험합니다

## 7. 품질 기준

전부 완벽할 필요는 없습니다. 아래만 지켜지면 됩니다.

1. **기준서 번호와 숫자가 원본과 같을 것** ← 가장 중요
2. 원본에 없는 문장이 들어가지 않았을 것
3. 불확실한 곳은 `[?...]`로 정직하게 표시돼 있을 것

읽기 어려운 부분이 남아 있어도 괜찮습니다. **모르는 걸 모른다고 표시한 결과물이, 매끄럽지만 틀린 결과물보다 낫습니다.**
