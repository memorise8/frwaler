1,245개 수집기 구조 정찰 — 2026-10-12

목표와 입력
site_tiers.csv의 1,245개 ID를 현재 registry와 정확히 대조하고 초기 단계와 근거를 보존한다.
납품 CSV의 모든 원본 URL을 우선 사용하며, 없는 사이트만 정적 코드/설정의 공개 URL을 사용한다.
정적 단계는 측정값과 분리한다. 공통 증분 개발과 기존 전수 수집 검증을 재개하지 않는다.
현재 미커밋 Asia Pacific 두 파일의 해시를 별도로 보존하며 수정하지 않는다.

실행
python -m delivery.scripts.discover_collection_structure --base <plan-dev-20261008> --workers 4
--site <ID> 반복 지정과 --limit N으로 표본 실행할 수 있다. 이미 결과가 있는 사이트는 재요청하지 않는다.
한 runner만 파일 잠금을 잡고 실행한다. 사이트 간 최대4개 병렬, 동일 호스트는 RequestGate로
직렬화하고 완료 후1.5초 간격을 유지한다. 신규 요청은 사이트당24회 이내, 최대 설정30회다.
중단된 사이트의 요청 이력도 재실행 예산에 포함한다. 출력 경로에 STOP 파일이 있으면 새 요청을
중단한다. 실행 중인 PID/호스트/시각/탐색기 해시는 runner.json에 남긴다.

수집하지 않는 항목
crawl(), DB 연결, 저장 메서드를 호출하지 않는다. 상세 문서와 PDF는 다운로드 대상으로 삼지 않는다.
GET 응답 헤더에서 문서/첨부 파일을 제외하고, 목록 응답은2MiB·시간 상한 안에서 메모리로만 읽는다.
파일에는 URL·ID·날짜·총량 후보·정렬/필터/페이지 제어·응답 해시와 요약만 저장한다.
인증·차단·JS 보안 챌린지는 호스트 접근 보류로 기록하며 우회하거나 다른 API를 시험하지 않는다.
일반 JS 목록은 needs_review로 남겨 필요한 경우에만 후속 Playwright 정찰로 확인한다.
운영/수집 DB 변경, 배포, 외부 발송, 데이터 삭제는 없다.

사이트별 관측
오래된 순 정렬, 마지막 페이지, 날짜/연도 필터, 상한/되돌아감, 가장 오래된 관측 ID/날짜,
독립 대조 근거, 식별값 안정성, 측정 서버/시각의8개 항목을 각 원본 범위에 기록한다.
게시된 정렬 링크/GET 폼만 시도하며 기존 범위 필터를 보존한다. 첫 화면의 마지막 번호는
끝으로 단정하지 않고, 이동 후 노출되는 더 큰 번호를 제한된 횟수만큼 추적한다.
마지막 후보 다음 페이지, 반복 조회의 ID, 게시된 사이트맵/robots 경로를 대조한다.
사이트맵 lastmod는 발행일이 아니며 사이트맵 항목 수는 원본 범위 문서 총량이 아니다.
행에서 찾은 날짜는 출처를 표시한다. 연도나 상대 날짜를 임의의 정확한 날짜로 바꾸지 않는다.
현재 가장 오래된 관측 항목과 전체 역사에서 가장 오래된 항목의 증명은 구분한다.

판정과 후속 작업
measured: 해당 정찰 방식의 접근/경계가 관측됨. 전체 문서 저장이나 전체 역사 완주를 뜻하지 않는다.
unmeasurable: 관측한 차단·오류·공개 진입점 부재 등 구체적 이유가 있음.
needs_review: JS/특수 목록, 불안정한 응답, 다른 방법과의 대조 미완료 등. 완료 개수에 넣지 않는다.
1차 실행이 끝나도 needs_review가 남으면 전용 읽기 전용 탐색 또는 필요한 브라우저 확인을 이어간다.
기본 탐색기로 이해하지 못한 결과를 사이트 자체의 불가 판정으로 바꾸지 않는다.

응답 요약의 별도 품질 검사
python -m delivery.scripts.review_structure_discovery --out <discovery-20261012>
이 명령은 네트워크/DB에 접근하지 않고 완료된 JSON만 읽는다. 원본 site JSON이나 실행 중인
progress/대장을 덮어쓰지 않고 quality-review.json과 followup-queue.json에 보수적인 판정을 기록한다.
8필드 누락, 요청 상한, 가장 오래된 ID/날짜 미확정, 마지막 페이지의 날짜 누락, 사이트맵 갱신일과
발행일 혼동, 반복 ID, 혼합 정렬, 되돌아감/조회 상한, 자체 redirect 등을 후속 확인 대상으로 분리한다.
따라서 1차 결과의 measured 개수와 이 품질 검사를 통과한 개수는 다를 수 있다. 최종 집계 전
검사 결과를 사이트별 근거와 대장에 반영해야 하며 needs_review는 완료로 세지 않는다.

후속 정찰 경로 추출
python -m delivery.scripts.route_structure_discovery --out <discovery-20261012>
모든1,245개 코드/설정에서 정적 목록 endpoint와 목록 파서의 CSS 선택자를 추출한다. 코드를
실행하거나 API에 접속하지 않는다. source-hints.json의 값은 단서이며 측정 완료 근거가 아니다.
followup-routing.json은 남은 요청 예산, 원본 범위 확인 조건, 기존 선택자/API/날짜 필터와
비보안 JS 화면의 브라우저 필요 가능성을 분리한다. 인증/차단/로그인/챌린지/속도 제한을
관측한 사이트는 다른 API 호스트가 코드에 있더라도 대체 접근 후보에서 제외한다.
이 단계도 실행 중인 1차 탐색기의 site JSON, progress, 대장을 덮어쓰지 않는다.
