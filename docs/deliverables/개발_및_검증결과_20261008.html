BUG-20261008-01 · 테스트 수집으로 인한 누락 가능성 조사 및 해소

수집 누락 영향 조사·복구 및 재발 방지 요청

업체가 기존 삭제·원복 문의를 ISSUE 01로 인한 테스트 수집 이후의 누락 가능성 조사·해소 요청으로 변경했다. 삭제나 원복 자체는 목표가 아니며 실제 누락 범위는 아직 확정하지 않았다.

  1. 고객의 실제 테스트 일시·시간대·사이트·작업·배포 버전을 특정한다. 테스트 이전/이후 문서·로그·커서·작업 상태를 읽기 전용으로 대조해 정상 자료와 영향 후보를 구분한다. 금일이라는 표현만으로 특정 날짜의 모든 문서를 대상으로 삼지 않는다.
  2. 사이트 원본 목록 또는 확보된 원본 응답과 DB 문서 식별값을 대조해 건수 제한·페이지 이동·중복 판단·재개 위치로 건너뛴 구간을 조사한다. DB에 이미 저장된 행만 검사해서 미수집 문서가 없다고 판정하지 않는다.
  3. 누락 확정·누락 의심·영향 없음·원본 접근 불가/근거 부족을 구분하고, 사이트별 영향 범위와 필요한 복구 방법을 보고한다. 원본이 바뀌었거나 당시 기록이 없으면 확인 가능한 범위와 불확실성을 남긴다.
  4. 누락 방지 수정과 기존 수집 결과를 보존하는 겹치는 구간 재탐색·보충 수집을 우선 검토한다. 커서 복원 또는 제한적인 원복이 필요한 경우에만 대상·이유·변경 예정 목록·백업·복구 절차를 마련한다. 문서 전체 삭제를 기본 해결책으로 삼지 않는다.
  5. 조치 시 수집·예약·번역·파일 작업의 동시 실행과 documents 참조 관계를 점검한다. 기존 seq_id·정상 문서·번역·요약·PDF/TXT 연결을 보존하고, cursor/items_done/completed_at의 일관성 및 작업 이력을 확인한다.
  6. 문제 구간을 재탐색/보충한 뒤 원본과 다시 대조하고, 3건 반복 실행·페이지 중간 종료·중단 후 재개에서 누락이 재발하지 않는지 검증한다. 코드 수정, 복구 도구 검증, 고객 데이터 실제 조치 완료를 분리해 기록한다.

완료 기준: 영향 대상 사이트·작업·구간의 조사 결과와 근거가 있고, 확인된 누락은 정상 자료와 파일 연결을 보존한 채 보충되며 재대조로 해소를 확인한다. 이후 제한 건수 반복·중단·재개에서도 해당 결함이 재발하지 않아야 한다. 미확인 구간·실환경 미조치는 남은 항목으로 표시하며, 삭제/원복 도구 구현이나 격리 테스트만으로 누락 해소 완료로 판정하지 않는다.

BUG-20261008-02 · published_date·listed_date 저장 형식 정규화

확인된 데이터 품질 버그

현재 공통 저장 경로가 서로 다른 날짜 문자열을 그대로 저장한다. 기존 날짜 조회·정렬은 이 혼합 형식을 일관되게 해석하지 못할 수 있다.

업체 해석대로 신규 수집 데이터의 규격화와 기존 수집 자료 보정 모두 포함한다. 규칙상 확정할 수 없는 값은 미해결 목록과 해석 상태로 관리한다.

  1. 각 수집기의 날짜 출처·언어·일/월 순서·정밀도를 조사하고, 발행일과 게시일의 의미를 별도로 유지한다.
  2. 완전한 날짜는 YYYY-MM-DD로 저장하는 공통 규칙을 정의한다. 숫자 날짜의 일/월 순서는 사이트 규칙으로 판단하고, 불명확한 값은 임의로 확정하지 않는다. 연도·월만 있는 날짜에 임의의 일을 채우지 않는다.
  3. 원문과 해석 상태를 보존할 저장 방식을 설계하고 SQLite/PostgreSQL 및 직접 저장 경로에 적용한다. 변환 불가·모호·부분 날짜의 처리와 조회 동작을 함께 정의한다.
  4. 기존 데이터는 변환 예정값·미해결 건수 dry-run 보고서를 만든 뒤 제한된 배치로 보정한다. seq_id·문서 식별값·파일 연결은 유지하고 반복 실행해도 결과가 같아야 한다.
  5. 날짜 범위 검색·정렬의 해석을 저장 규칙과 맞추고, 기존 비정규 데이터가 조용히 누락되는 경우를 점검한다.

완료 기준: 신규 수집 저장 경로에 날짜 규격화를 적용하고 기존 자료의 보정 대상·처리 결과·미해결 목록을 남긴다. 2026-08-07은 유지, 일-월-연도 규칙이 확인된 07.08.2026은 2026-08-07, 02 octobre 2026은 2026-10-02가 된다. 모호한 날짜·불가능한 날짜·부분 날짜를 날조하지 않으며 발행일과 게시일은 서로 다른 값을 유지할 수 있다. 기존 자료 보정과 검색·정렬 검증을 통과해야 한다.

BUG-20261008-03 · 전체 수집 데이터의 문서 식별값 검증·파싱 수정 및 기존 자료 보정

KRIVET 확정 결함 + 전 사이트 기존 데이터 품질 검증 요청

KRIVET은 재현된 예시 중 하나다. 업체는 site_id·post_number 중복이 다른 사이트에서도 나온다고 제보하며 전체 수집 데이터 검증을 요청했다. 제보 SQL의 결과 행/건수와 다른 사이트의 실제 결함 여부는 아직 이 세션에서 조회·확정하지 않았다.

  1. 검증 대상 documents 전체를 site_id별로 조사한다. KRIVET이나 유사 URL 유형, 납품 목록 806개에만 한정하지 않고 실제 저장된 모든 사이트를 포함하며, 대상 DB·조회 시점·전체/사이트별 건수·검사 범위를 기록한다.
  2. 업체 제공 SQL을 출발점으로 site_id·post_number 중복 그룹과 NULL/빈 값/공백 식별값을 집계한다. 서로 다른 meta_url 수와 원본 문서 식별값, 게시판·자료 유형 등 ID가 유일한 범위를 함께 대조한다. 그룹 전체를 무조건 오류 또는 삭제 대상으로 삼지 않는다.
  3. 잘못된 키 추출(메뉴/분류 번호 등), 같은 문서의 중복 저장(URL 변형 포함), 서로 다른 문서의 키 충돌, 게시판별 번호 재사용 등 정상 사례, 식별값 누락, 판단 보류로 분류한다. 중복 그룹 밖에도 잘못된 식별값이 있을 수 있어 ID 존재·형식·URL/원본 일치 검사를 전체에 적용 가능한 범위까지 수행한다.
  4. 사이트별 올바른 문서 식별 규칙과 중복 판단 범위를 정의하고 오류가 확인된 모든 대상 수집기의 파싱·저장 경로를 수정한다. KRIVET은 menuSn 대신 pstNo를 사용한다. (site_id, post_number) UNIQUE를 근거 없이 전체 사이트에 추가하거나 파서를 일괄 치환하지 않는다.
  5. 기존 자료 전체 조사에서 확인된 오류를 사이트별로 보정한다. dry-run에 seq_id·현재 키·예정 키·근거·충돌·참조 영향을 기록하고, 기존 seq_id 및 번역·요약·PDF/TXT 연결을 유지한다. 충돌/실제 중복은 별도 해결 규칙을 정하며 임의 삭제·병합하지 않는다.
  6. 신규 코드 배포와 기존 자료 보정 사이 서로 다른 키로 재수집되는 것을 막는 적용 순서를 정한다. 보정 후 전체 동일 검사를 다시 수행해 오류 감소·정상 중복 사유·미해결 건수를 대조하고, 수정 사이트별 재수집 시 추가 중복·누락이 없는지 검증한다.
  7. 전체 데이터 품질 결과표에 날짜 품질(BUG-02), 문서 URL/필수 필드 누락, 문서-번역/요약/파일 작업 참조 일관성도 연결해 기록한다. 실제 PDF/TXT 파일 내용 검사는 전수인지 표본인지 별도 표시하고 DB 플래그 확인을 파일 검증으로 간주하지 않는다.

완료 기준: 실제 저장된 모든 사이트와 documents 행에 대해 식별값 검사의 적용 범위·건수·분류 근거가 기록되어야 한다. 오류가 확인된 수집기는 신규 문서를 올바른 식별값으로 저장하고 기존 오류 자료도 보정한다. KRIVET 2건만 성공한 것으로 완료 처리하지 않는다. 보정 전후 집계·충돌 처리·참조 보존·재실행 동일 결과·재수집 중복/누락 여부를 검증한다. 정상적인 키 중복은 근거를 남겨 유지하며 중복 그룹 0개를 일률적인 완료 기준으로 삼지 않는다. 실DB 미접근·원본 미확인·미해결 자료는 명시하고 전체 데이터 보정 완료로 판정하지 않는다.

전체 키 중복 후보 집계

SELECT count(*) AS cnt, d.site_id, d.post_number
FROM documents AS d
GROUP BY d.site_id, d.post_number
HAVING count(*) > 1
ORDER BY cnt DESC;

업체 제보 SQL과 같은 집계 의미의 읽기 전용 예시다. 이번 문서 보완에서 실행하지 않았다. 결과는 의심 후보이며 오류·삭제 대상 확정이 아니다.
