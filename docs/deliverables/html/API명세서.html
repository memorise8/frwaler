1.문서 개요

프로젝트명웹페이지 데이터 수집·분석·요약 서비스 (libertree)
문서 종류API 명세서 (API Specification) — 클라이언트 납품용
대상 독자발주처 담당자, 운영/유지보수 인력, 프론트엔드·백엔드 개발자
최초 작성 기준일2026-08-01
갱신일2026-08-01

본 문서는 실제 소스 코드에 구현된 HTTP 엔드포인트를 코드 기준으로 정확히 기술한다. 계약서상 명시된 기술 스택과의 차이는 부록에서 별도로 설명한다.

본 서비스는 세 개의 독립 실행 컴포넌트로 구성된다.

  1. FastAPI Crawler API (api/) — Python FastAPI 기반의 Auto-Add 작업용 경량 API.
  2. finolaw 관리자 애플리케이션 (finolaw/) — Next.js Route Handler 기반의 운영/관리 대시보드 백엔드. 크롤링 실행·요약·문서 서빙 등 쓰기 작업을 포함한다.
  3. libertree-app 열람 애플리케이션 (libertree-app/) — Next.js Route Handler 기반의 읽기 전용(read-only) 열람 서비스.

2.공통 사항

2.1 Base URL / 포트

컴포넌트개발 Base URL비고
finolaw 관리자 앱http://localhost:3001Next.js. 모든 관리 API의 prefix는 /api
libertree-app 열람 앱http://localhost:3000Next.js. 읽기 전용
FastAPI Crawler API(별도 실행)CORS 허용 오리진은 http://localhost:3001, http://localhost:30003 (api/settings.py). 포트는 실행 시 지정
참고: FastAPI Crawler API는 별도의 독립 프로세스이며, finolaw 앱은 이와 별개로 Python 크롤러를 python -m crawler.main ... 서브프로세스로 직접 구동한다. 두 경로 모두 실제 코드에 존재한다.

2.2 인증 방식

컴포넌트인증구현
finolawHTTP Basic AuthNext.js Proxy(구 middleware) finolaw/src/proxy.ts가 정적 자산·Next 내부 경로를 제외한 모든 요청을 가로채 검증. 인증 로직은 src/lib/internal-auth.ts
libertree-appHTTP Basic Auth각 Route Handler 내부에서 authenticateInternalRequest() 직접 호출 (src/lib/internal-auth.ts). 읽기 전용 서비스이나 접근에는 인증 필요
FastAPI Crawler API없음 (엔드포인트 레벨)Basic Auth 미적용. /api/auto-add는 OPENAI_API_KEY 환경변수 존재 여부만 검사

Basic Auth 상세 (finolaw / libertree-app 공통):

  • 자격증명은 환경변수 ADMIN_USER / ADMIN_PASSWORD로 설정한다.
  • Authorization: Basic <base64(user:password)> 헤더로 전달.
  • 사용자명·비밀번호는 상수 시간 비교(constant-time comparison)로 검증하여 타이밍 공격을 방지한다.
  • 인증 결과는 세 가지 상태를 가진다.
    • authorized — 정상 통과.
    • misconfigured — ADMIN_USER/ADMIN_PASSWORD 미설정. HTTP 503, 본문 "Internal authentication is not configured" 반환(fail-closed).
    • unauthorized — 자격증명 누락/불일치. HTTP 401, 헤더 WWW-Authenticate: Basic realm="Libertree Internal", charset="UTF-8" 반환.
  • libertree-app은 추가로 데이터 경로 계약(data contract) 설정 여부도 검사하며, 미설정 시 misconfigured(503)로 처리한다.

2.3 공통 에러 형식

전역 표준 에러 스키마는 코드에 정의되어 있지 않으며, 컴포넌트/엔드포인트별로 형식이 다르다. 실제 패턴은 다음과 같다.

유형형식예시
finolaw 일반 APIJSON { "error": "<메시지>" }{ "error": "invalid siteId" } (400)
finolaw summarizeJSON { "ok": false, "error": "<메시지>" } (+ 선택적 stderr){ "ok": false, "error": "docId must be a positive integer" } (400)
finolaw blob / libertree-apptext/plain 본문(짧은 문자열)"invalid seq_id", "blob not found" (404)
Basic Auth 실패text/plain 본문"Authentication required" (401) / "Internal authentication is not configured" (503)
FastAPIJSON { "detail": "<메시지>" } (FastAPI HTTPException 기본형){ "detail": "OPENAI_API_KEY not configured. ..." } (400)
SSE 스트림 내 오류이벤트 페이로드 { "type": "error", "message": "..." }스트림 본문 내 전달

2.4 데이터 소스

  • 저장소는 SQLite 데이터베이스이다.
    • finolaw / libertree-app: data/libertree.db (프로젝트 루트 기준, Next.js process.cwd()의 상위 디렉터리). documents 테이블이 핵심 스키마이며 선택적으로 sites 테이블과 조인한다.
    • FastAPI: 기본값 data/papers.db (api/settings.py의 database_url, 환경변수 CRAWLER_DATABASE_URL로 재정의 가능).
  • 원문 파일(PDF/TXT)은 seq_id를 12자리 zero-pad한 경로 규칙으로 디스크에 저장되며 blob 서빙 엔드포인트를 통해 스트리밍된다.
  • 크롤러 로그는 프로젝트 루트의 .cache/ 디렉터리에 *.log 파일로 축적된다.

4.엔드포인트 상세

4.A 시스템 / 헬스

A-1. GET /api/health — FastAPI 헬스 체크

  • 컴포넌트: FastAPI Crawler API (api/main.py)
  • 목적: 서비스 생존 확인.
  • 인증: 없음.
  • Path/Query 파라미터: 없음.
  • 요청 본문: 없음.
  • 응답 (200):
{ "status": "ok" }

A-2. GET /api/health — finolaw 사전 점검(preflight)

  • 컴포넌트: finolaw (finolaw/src/app/api/health/route.ts → src/lib/preflight.ts)
  • 목적: 크롤러 실행에 필요한 런타임/환경 요소가 준비되었는지 종합 점검.
  • 인증: Basic Auth.
  • Path/Query 파라미터: 없음.
  • 요청 본문: 없음.
  • 응답 필드 (PreflightStatus):
필드타입설명
status"ok" | "warning" | "error"전체 종합 상태. 하나라도 error면 error, 아니면 warning 존재 시 warning, 그 외 ok
projectRootstring프로젝트 루트 절대경로
checkedAtstring (ISO8601)점검 시각
checksarray개별 점검 항목 배열

각 checks[] 항목(PreflightCheck):

필드타입설명
idstring점검 항목 식별자
labelstring표시명
level"ok" | "warning" | "error"항목 상태
messagestring상태 메시지(한국어)
detailstring (선택)상세(경로/키 등)

점검 항목 id 목록: crawler-dir(Python 크롤러 패키지, 미존재 시 error), python(Python 런타임, error), database(SQLite DB data/libertree.db, 미존재 시 warning), cache-dir(로그 캐시 디렉터리, warning), openai-api-key(OpenAI 키 유무), codex-cli(Codex CLI PATH 존재 여부), admin-auth(ADMIN_USER/ADMIN_PASSWORD 설정 여부).

  • 상태 코드: status === "error" → 503, 그 외 → 200.

A-3. GET /api/health — libertree-app 카탈로그 준비 상태

  • 컴포넌트: libertree-app (libertree-app/src/app/api/health/route.ts)
  • 목적: 읽기 전용 카탈로그 데이터 접근 계약이 유효한지 확인.
  • 인증: Basic Auth (authenticateInternalRequest 직접 호출).
  • Path/Query 파라미터: 없음.
  • 요청 본문: 없음.
  • 동작: verifyCatalogueReadiness() 실행 후 성공/실패에 따라 응답.
  • 응답 (200, 준비 완료):
{ "status": "ready", "mode": "read-only", "contract": "validated" }

  • 그 외 예외는 상위로 전파된다(500 계열).

4.B 크롤러 관리

B-1. GET /api/crawler — 실행 중 작업 + 로그 목록

  • 컴포넌트: finolaw (crawler/route.ts → src/lib/crawler-runner.ts)
  • 목적: 현재 실행 중인 크롤러 작업과 .cache/ 내 로그 파일 목록 조회.
  • 인증: Basic Auth.
  • 파라미터/본문: 없음.
  • 응답 (200):
{
  "jobs": [
    { "jobId": "...", "pid": 12345, "siteId": "...", "logPath": "...", "startedAt": "ISO8601" }
  ],
  "logs": [
    { "name": "ui_....log", "size": 1024, "mtime": "ISO8601" }
  ]
}
  • jobs: 메모리 상 등록된 작업 중 PID가 살아있는 것만 반환(listRunningJobs가 죽은 PID를 정리).
  • logs: .cache/의 *.log 파일을 mtime 내림차순 정렬.
주의: 작업 목록은 서버 프로세스 인메모리 Map에 저장된다. 서버 재시작 시 소실되며 서버 인스턴스 간 공유되지 않는다.

B-2. POST /api/crawler — 크롤러 시작/중지

  • 컴포넌트: finolaw (crawler/route.ts)
  • 목적: action에 따라 크롤러 서브프로세스(python -m crawler.main crawl ...) 시작 또는 중지.
  • 인증: Basic Auth.
  • 요청 본문 (JSON):
필드타입필수설명
action"start" | "stop"예동작 구분
siteIdstringstart 시 필수사이트 ID. 정규식 ^[a-z0-9][a-z0-9\-_]{1,63}$ 검증(소문자·숫자·하이픈·언더스코어, 2–64자)
docTypestring아니오문서 유형 필터
incrementalboolean아니오증분 크롤링 여부
limitnumber아니오수집 개수 제한
jobIdstringstop 시 필수중지할 작업 ID
  • 응답 (200, start):
{ "job": { "jobId": "<siteId>-<docType|all>-<timestamp>", "pid": 12345, "siteId": "...", "logPath": "...", "startedAt": "ISO8601" } }
  • 응답 (200, stop):
{ "stopped": true }
  • stopped는 해당 jobId가 존재하고 SIGTERM 전송에 성공하면 true, 아니면 false.
  • 에러:
    • 400 { "error": "invalid siteId" } — start인데 siteId 누락/형식 불일치.
    • 400 { "error": "jobId required" } — stop인데 jobId 누락.
    • 400 { "error": "unknown action" } — action이 start/stop이 아님.

B-3. GET /api/crawler/sites — 크롤 가능한 사이트 목록

  • 컴포넌트: finolaw (crawler/sites/route.ts → src/lib/db.ts::getSiteOptionsRich)
  • 목적: 크롤러 실행 대상으로 선택 가능한 사이트 ID 목록 제공.
  • 인증: Basic Auth.
  • 파라미터/본문: 없음.
  • 동작: 다음 3개 소스를 합집합·정렬하여 반환한다.
    1. libertree.db에 이미 수집된 사이트(getSiteOptionsRich()의 site_id).
    2. crawler/sites/configs/*.json 선언형 설정 파일명.
    3. crawler/sites/custom/*.py 커스텀 크롤러 파일명.
    • DB 접근 실패 시 디스크 소스만으로 폴백한다.
  • 응답 (200):
{ "sites": ["site-a", "site-b", "..."] }
  • sites: 문자열 배열(중복 제거·오름차순 정렬).

B-4. GET /api/crawler/logs — 로그 파일 tail SSE 스트림

  • 컴포넌트: finolaw (crawler/logs/route.ts)
  • 목적: 지정한 로그 파일을 실시간 tail 하여 Server-Sent Events로 스트리밍.
  • 인증: Basic Auth.
  • Query 파라미터:
파라미터타입필수설명
filestring예로그 파일명. .log로 끝나야 하며 경로 구분자(/, \) 포함 불가. .cache/ 하위로 정규화 검증
  • 동작:
    • 최초 연결 시 파일 마지막 약 100줄을 즉시 전송.
    • 이후 fs.watch로 파일 증가분을 감지하여 새 줄을 전송. 파일 truncate 시 위치를 0으로 재설정.
    • 클라이언트 연결 종료(abort) 시 watcher/파일 핸들 정리.
  • 응답 헤더: content-type: text/event-stream, cache-control: no-cache, no-transform, x-accel-buffering: no, connection: keep-alive.
  • 응답 본문 형식: SSE, 각 줄 data: <로그 한 줄>\n\n.
  • 에러:
    • 400 "invalid file" — file 누락/형식 위반.
    • 403 "forbidden" — 정규화 경로가 .cache/ 밖.
    • 404 "not found" — 파일 미존재.

4.C Auto-Add · Smart-Find

C-1. POST /api/auto-add — Auto-Add 작업 시작 (FastAPI)

  • 컴포넌트: FastAPI Crawler API (api/routers/auto_add.py)
  • 목적: AI 에이전트(crawler.agent.AutoAddAgent)를 백그라운드 스레드로 실행해 URL로부터 사이트를 자동 등록.
  • 인증: 엔드포인트 레벨 없음. 단, OPENAI_API_KEY 환경변수가 없으면 즉시 실패.
  • 요청 본문 (AutoAddRequest, JSON):
필드타입필수기본값설명
urlstring예—대상 URL
site_idstring | null아니오null사이트 ID 지정(선택)
browserboolean아니오false브라우저 강제 사용 여부
  • 동작: 작업을 생성(create_job)하고 데몬 스레드로 에이전트를 실행한 뒤, 즉시 생성된 작업 객체를 반환한다(비동기, 완료를 기다리지 않음).
  • 응답 (200) — 작업 객체(job_manager 스키마):
필드타입설명

typestring"auto-add"

resultstring | null결과 문자열(성공 시 등록 사이트/발견 항목 수, 실패 시 사유)
diagnosislist | null진단 정보
참고: 작업 상태 조회용 별도 GET 엔드포인트는 현재 라우터에 등록되어 있지 않다(작업 상태는 인메모리 _jobs 딕셔너리에 저장됨). 폴링 엔드포인트 부재는 개선 여지로 기록한다.

E-1. GET /api/blob/{seq_id}/{ext} — 원문 파일 서빙 (finolaw)

  • 컴포넌트: finolaw (blob/[seq_id]/[ext]/route.ts → src/lib/db.ts)
  • 목적: 수집된 원문 파일(PDF/추출 TXT)을 디스크에서 스트리밍.
  • 인증: Basic Auth. Proxy 미들웨어에 더해 라우트 내부에서 authenticateInternalRequest()를 한 번 더 호출한다.

파라미터타입설명
seq_idstring문서 순번. ^\d{1,12}$, 0 이상 1e12 미만 정수
extstringpdf 또는 txt(대소문자 무시). 그 외는 404

    1. getDocumentBlobInfo(seqId)로 original_filename, pdf_downloaded, text_extracted, site_id 조회.

  • 에러(모두 404, text/plain 본문): "invalid seq_id", "unsupported extension", "blob not found", "blob not found: <seq>.<ext>", "not a file". 인증 실패 시 401/503(§2.2).

E-2. GET /api/blob/{seq_id}/{ext} — 원문 파일 서빙 (libertree-app)

  • 컴포넌트: libertree-app (blob/[seq_id]/[ext]/route.ts → src/lib/catalogue.ts)
  • 목적: 읽기 전용 열람 앱에서 원문 파일 서빙.
  • 인증: Basic Auth (authenticateInternalRequest() 직접 호출).
  • Path 파라미터: finolaw E-1과 동일(seq_id: ^\d{1,12}$ & safe integer, ext: pdf/txt).
  • 동작:
    1. getBlobAuthorization(seqId, ext) 조회 → { available: boolean, originalFilename: string | null }. available은 확장자에 따라 pdf_downloaded/text_extracted가 1인지로 결정.
    2. available이 아니거나 결과가 없으면 404.
    3. blobPathFor(seqId, ext) 경로에서 파일 스트리밍.
  • 응답 (200): 파일 바이트 스트림.
    • 헤더: content-type(application/pdf 또는 text/plain; charset=utf-8), content-length, content-disposition: inline; filename="<basename(path)>", cache-control: private, max-age=0, must-revalidate.
    • 참고: finolaw(E-1)와 달리 파일명은 디스크 경로의 basename을 사용하며 RFC5987 filename*은 부여하지 않는다.

5.부록: 실제 구현 스택

5.1 계약 대비 실제 스택 변경

구분계약서 명시실제 구현
백엔드 프레임워크Django / Django REST Framework (DRF)FastAPI (Auto-Add 전용 경량 API) + Next.js Route Handlers(finolaw / libertree-app의 관리·열람 API 전반)
API 계층DRF ViewSet/SerializerFastAPI APIRouter + Next.js App Router route.ts 핸들러
데이터베이스(동일) SQLiteSQLite (data/libertree.db, FastAPI는 data/papers.db)

변경 사유: 경량화 및 통합. 프론트엔드(Next.js)와 API를 하나의 애플리케이션(Route Handlers)으로 통합하여 별도 백엔드 서버 운영 부담을 줄이고, 크롤러 파이프라인은 Python 서브프로세스(python -m crawler.main ...)로 직접 호출하는 구조를 채택했다. AI 에이전트 기반 Auto-Add만 독립 FastAPI 서비스로 분리하여 비동기 백그라운드 처리를 담당한다. Django/DRF의 무거운 ORM·미들웨어 스택 없이 동일 기능을 더 가볍게 제공하는 것이 목적이다.

5.2 요약(Summarization) 엔진

  • 문서 요약은 로컬 Ollama 모델로 생성한다. 프로덕션 요약 66,248건의 실측 분포(summary_model 기준): gemma4:26b 36,548건(55%) + qwen3:8b 29,700건(45%).
  • 코드(crawler/summarizer.py)에는 OpenAI(gpt-5.4-mini)·Gemini(gemini-2.5-flash) 경로도 있으나 프로덕션 요약에는 미사용이다. 계약(REQ-2026-001)은 OpenAI API였으나 비용·온프레미스 이유로 로컬 모델로 구현했다. (향후 전문용어 등에서 OpenAI 폴백 도입은 계획.)
  • 요약 실행은 finolaw POST /api/admin/summarize가 트리거하며, 실제 처리는 Python 크롤러(crawler.main summarize)가 수행한다. --provider로 gpt/openai/gemini/google을 선택적으로 지정할 수 있다(코드상 허용값).

5.3 아키텍처 특기 사항 (운영 참고)

  1. 인메모리 작업 상태: finolaw의 크롤러/Auto-Add/Codex 작업 목록과 FastAPI의 Auto-Add 작업 상태는 모두 서버 프로세스 메모리에 저장된다. 서버 재시작 시 소실되며 다중 인스턴스 간 공유되지 않는다. 영속 작업 이력이 필요하면 별도 저장소 도입이 필요하다.
  2. FastAPI Auto-Add 폴링 부재: POST /api/auto-add는 작업을 즉시 반환하지만, 진행/완료를 조회하는 GET 엔드포인트가 현재 라우터에 등록되어 있지 않다(코드 기준). 상태 폴링이 필요하면 추가 구현이 요구된다.
  3. 이중 인증(blob): finolaw의 blob 라우트는 Proxy 미들웨어와 라우트 내부 검증을 이중으로 수행한다.
  4. SSE 사용: /api/crawler/logs, /api/smart-find는 Server-Sent Events 스트림이며 일반 JSON 응답이 아니다. 클라이언트는 EventSource 또는 스트림 파서로 소비해야 한다.

본 명세서는 소스 코드(2026-08-01 기준)를 직접 분석하여 작성되었으며, 코드에 없는 동작은 추정하지 않고 명시적으로 표기하였다.
