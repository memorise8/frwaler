본 매뉴얼은 finolaw 관리자 웹앱의 실제 화면과 동작을 기준으로 작성되었습니다. 각 화면에서 제공하는 버튼·필드·컬럼을 실제 코드 기준으로 설명하며, 존재하지 않는 기능은 "제공되지 않음"으로 명시합니다.

finolaw는 전세계 정부·연구·학술 사이트의 문서를 수집(크롤링) → PDF 다운로드 → 텍스트 변환 → AI 요약 단계로 처리하고, 그 현황과 결과를 웹에서 확인·검색·재요약할 수 있는 관리 도구입니다. 데이터는 저장소 루트의 libertree.db (SQLite)에 적재되며, 대부분의 화면은 읽기 전용 집계를 보여 줍니다.

2. 시작하기

2.1 접속 URL

구분값
접속 주소http://localhost:3001
실행 포트3001 (next dev -p 3001 / next start -p 3001)
참고: 화면 우측 상단 헤더에 port 3002 라는 회색 라벨이 표시되지만, 이는 코드에 고정된 표시용 문자열일 뿐 실제 서비스 포트가 아닙니다. 실제 접속 포트는 3001입니다.

2.2 로그인 (HTTP Basic 인증)

finolaw는 별도의 로그인 화면이 없습니다. 브라우저로 처음 접속하면 운영체제/브라우저 기본 HTTP Basic 인증 팝업이 뜹니다.

  • 사용자명 / 비밀번호: 서버 환경변수 ADMIN_USER / ADMIN_PASSWORD 에 설정된 값
  • 인증 영역(realm) 표시: Libertree Internal
  • 인증은 정적 자산(css/js/이미지 등)과 Next.js 내부 경로를 제외한 모든 페이지에 적용됩니다.
  • 인증 처리는 src/proxy.ts (Next.js 16 proxy)에서 수행되며, 아이디/비밀번호 비교는 타이밍 공격 방지를 위해 상수시간 비교를 사용합니다.

인증 관련 응답 상태

상황HTTP 상태의미
아이디/비밀번호 미설정503서버에 ADMIN_USER/ADMIN_PASSWORD 환경변수가 비어 있음 → 운영자에게 환경변수 설정 요청
자격 증명 누락/오류401팝업 취소 또는 잘못된 계정 입력 → 재입력
정상 인증200페이지 정상 표시
503이 뜨면 계정 문제가 아니라 서버 환경변수 미설정 문제입니다. 대시보드 상단의 사전점검(Preflight) 배너에도 관리자 인증 상태가 함께 표시됩니다(2.4 참고).
[스크린샷: 브라우저 Basic 인증 팝업]

2.3 네비게이션 개요

모든 화면 상단에는 공통 헤더가 고정되어 있으며, 좌측에 🌳 Libertree 로고(클릭 시 대시보드로 이동)와 다음 7개 메뉴가 나열됩니다. 우측에는 라이트/다크 테마 토글 버튼이 있습니다.

7크롤러 관리⚙️/crawler크롤러 수동 실행·로그 스트리밍

2.4 사전점검(Preflight) 배너

대시보드 접속 시 시스템 상태에 문제가 있으면 상단에 경고/오류 배너가 나타납니다. DB, Python, Codex, API 키, 관리자 인증 상태를 점검한 결과이며, 우측 "JSON 보기" 링크(/api/health)로 상세 상태를 확인할 수 있습니다. 이상이 없으면 배너는 표시되지 않습니다.

3. 화면별 사용법

3.1 대시보드 (수집 현황 요약) — /

목적
전체 수집 현황을 한 화면에서 파악합니다. 총 문서/사이트 수, 처리 단계별 통과율, 대륙·국가·범주별 분포, 최근 수집 사이트, 입력→수집 퍼널을 보여 줍니다.

주요 항목·컨트롤

  • 상단 우측
    • "마지막 수집: {일시}" — 가장 최근 크롤링 시각
    • 전체 MD export 버튼 — 전체 문서를 Markdown으로 내보내기(/api/export/markdown)
  • KPI 카드 4종
    • 총 문서 수 (최근 수집 일시)
    • 총 사이트 수 (등록 메타 건수)
    • PDF 보유 (전체 대비 %)
    • TXT 추출 (전체 대비 %)
  • 입력 → 등록 → 수집 Funnel (입력 CSV가 있을 때만 표시)
    • 막대: 입력 entries → unique hosts → 등록 크롤러 → 수집 완료
    • 회복 카테고리 분류(자동회복중/수집완료/회원가입 필요/정책상포기/절대불가/미분류)
    • "되는 것 / 안 되는 것" 요약 카드: ✅ 수집 가능 / 🔐 수동 회복 / ❌ 회복 불가
    • "카테고리 의미 설명" 펼치기로 각 분류 정의 확인
  • 대륙별 분포 표 (사이트/문서/PDF/TXT/비중)
  • 국가별 상위 10개 표
  • 범주별 분포 표
  • 최근 수집 사이트 표 (사이트/국가·범주/문서 수/최근 수집/문서 보기 바로가기) — 최근 8개
  • 바로가기 카드 4종: 문서 검색 · 수집 현황 · URL 크롤링 · 크롤러 관리

사용 절차

  1. 상단 네비에서 🌐 대시보드 클릭(또는 로고 클릭).
  2. KPI 카드로 전체 규모와 단계별 통과율을 확인.
  3. 분포 표에서 특정 대륙/국가/범주 비중을 확인.
  4. "최근 수집 사이트" 표의 문서 보기를 눌러 해당 사이트 문서를 검색 화면에서 확인.
  5. 데이터 백업/공유가 필요하면 전체 MD export 클릭.
데이터가 없으면 "아직 수집된 문서가 없습니다." 안내가, DB 연결 실패 시 빨간 오류 박스(예상 경로 ../data/libertree.db)가 표시됩니다.
[스크린샷: 대시보드]

3.2 문서 검색 — /search

목적
전세계 정부·연구·학술 사이트에서 수집된 문서를 키워드와 다중 필터로 통합 검색합니다.

주요 항목·컨트롤

  • 검색어 입력창 — 제목·본문·키워드·저자 대상 검색
  • 구조 필터 (드롭다운 4종): 대륙 / 국가 / 범주 / Sheet
    • 대륙을 고르면 국가·범주·Sheet 목록이 그 대륙에 맞춰 좁혀집니다(점진적 필터링).
  • 사이트 (선택) 드롭다운 — 개별 사이트 지정. 옵션에 사이트명·국가·문서 수가 함께 표시됩니다.
  • 발행일 범위 — YYYY-MM-DD 형식의 "부터" / "까지" 입력
  • 결과 요약 줄 — 결과 건수 · 대상 사이트 수 · 현재/전체 페이지
  • 초기화 링크 / 검색 버튼
  • 결과 목록 — 각 항목에 제목, 국가 배지, 범주 배지, 발행일, 출처명, 소개(요약 또는 초록) 미리보기 표시. 항목 클릭 시 문서 상세(/search/{id})로 이동.
  • 페이지네이션 — 페이지당 20건, 이전/다음 이동

사용 절차

  1. 상단 네비에서 🔍 문서 검색 클릭.
  2. 검색어를 입력하고 필요 시 대륙→국가→범주→Sheet, 사이트, 발행일을 지정.
  3. 검색 버튼 클릭.
  4. 결과 목록에서 문서 제목을 클릭해 상세 확인.
  5. 조건을 바꾸려면 값 변경 후 다시 검색, 전체 초기화는 초기화 클릭.
수집 데이터가 아직 없으면 상단에 노란 안내 박스와 DB 경로가 표시됩니다.
[스크린샷: 문서 검색]

3.3 문서 상세 (관리자 raw 검증) — /admin/document/{seq_id}

목적
개별 문서의 DB 원본 값을 그대로 검증하는 관리자 전용 페이지입니다. 일반 열람용(/search/{id})과 달리, 모든 DB 필드·블롭 파일 존재 여부·원본 JSON을 노출합니다.

주요 항목·컨트롤

  • 상단 링크: ← /search/{12자리 seq_id} (공개 열람 페이지), · /admin/status (수집 현황)
  • 헤더 카드: seq_id(원본/12자리 패딩), site_id, post_number
  • 필드 표 (필드 / DB 값 / 비고) — 주요 필드:
    • collected_at, site_id(+ site_name JOIN), post_number(점진수집 키)
    • title, published_date(작성/출판일), listed_date(사이트 게시일)
    • authors(분리 결과), publisher(기관 분리), journal
    • meta_url, pdf_url (새 탭 링크)
    • keywords(분리 결과), abstract(펼치기, 글자수)
    • original_filename
    • pdf_downloaded, text_extracted (각 디스크 존재 여부 ✓/✗)
    • pdf_size_bytes, pdf_sha256
    • summary(펼치기, 글자수), summary_model(요약에 사용된 모델), summary_at(요약 시각)
    • site_name, site_url (sites 테이블 JOIN)
  • 블롭 파일 섹션 — pdf, txt 각각에 대해:
    • 저장 경로, ✓ exists / ✗ missing 배지
    • 파일이 존재하면 [download] 링크(/api/blob/{seq_id}/{ext})로 원본 다운로드
    • db_flag / db_size / disk_size 비교값
  • raw JSON dump — 문서 레코드 전체를 JSON으로 출력(절대경로 필드는 제외)

사용 절차

  1. 검색 결과·수집 현황·요약 결과 등에서 특정 문서로 진입(또는 URL에 seq_id 직접 입력).
  2. 필드 표에서 메타데이터가 올바르게 수집되었는지 확인.
  3. 블롭 파일 섹션에서 PDF/TXT 존재 여부를 점검하고, 필요 시 [download] 로 원본 파일 확인.
  4. summary / summary_model / summary_at 로 요약 생성 여부와 사용 모델을 확인.
잘못된/존재하지 않는 seq_id는 404(문서 없음) 처리됩니다. 이 화면에는 재수집·재추출·재요약 버튼이 없습니다(검증 전용). 재요약은 3.4 요약 결과 화면에서 수행합니다.
[스크린샷: 문서 상세(관리자 raw 검증)]

3.4 요약 결과 · 재요약 — /admin/summary

목적
AI 요약(documents.summary)의 생성 상태를 확인하고, 필요한 문서를 재요약합니다.

주요 항목·컨트롤

  • 필터 폼
    • 상태 드롭다운: 전체 / 요약 완료 / 미요약
    • 사이트 드롭다운: 전체 사이트 또는 개별 사이트(사이트명 + site_id)
    • 적용 버튼 / 초기화 링크
    • 우측에 "전체 N건 · 페이지 x/y" 표시
  • 문서 목록 (페이지당 30건) — 각 행:
    • 제목(클릭 시 /search/{id} 상세로 이동)
    • #{문서ID} 배지, site_id 배지
    • 요약 완료(초록색) 또는 미요약(노란색) 상태 배지
    • 요약이 있으면 요약 본문 표시, 없고 초록이 있으면 "초록:" 미리보기(240자) 표시
    • 우측 재요약 버튼
  • 재요약 버튼 동작
    • 클릭 시 POST /api/admin/summarize(본문 { docId }) 호출
    • 진행 중에는 버튼이 "요약 중…" 으로 바뀌고 비활성화
    • 완료되면 서버 데이터가 새로고침되어 갱신된 요약이 즉시 표시
    • 실패 시 버튼 옆에 오류 메시지가 빨간 글씨로 표시
    • 요약 처리는 서버에서 python -m crawler.main summarize --doc-id {id} 를 실행하며, 90초 타임아웃이 적용됩니다.
  • 페이지네이션 — 이전/다음 이동

사용 절차

  1. 상단 네비에서 🧠 요약 결과 클릭.
  2. 상태를 미요약으로, 필요 시 사이트를 선택한 뒤 적용 클릭.
  3. 목록에서 대상 문서를 확인하고 각 행의 재요약 클릭.
  4. 버튼이 "요약 중…"에서 원래대로 돌아오고 요약 본문이 채워지면 완료.
  5. 오류 메시지가 나오면 내용을 확인(예: 모델/키 문제)하고 재시도.
이 화면의 재처리는 요약(summary)만 지원합니다. 텍스트 추출·PDF 재다운로드 재처리 버튼은 없습니다.
[스크린샷: 요약 결과 · 재요약]

3.5 수집 보고서 (오류·예외) — /admin/collection-report

목적
입력부터 요약까지의 현재 상태를 집계하고, PDF 다운로드 실패를 사이트별로 진단합니다. 읽기 전용 리포트입니다. (상단 네비에는 없으며 URL로 접근하거나 리포트 내 이동 링크를 사용합니다.)

주요 항목·컨트롤

  • 리포트 헤더 — 상단 이동 링크: 홈 / 사이트 진행도(/admin/status) / 요약(/admin/summary)
  • STATUS (상태 밴드) — "읽기 전용 집계" 배지와 함께
    • 입력 URL(고유 호스트 수), 등록 수집기, 수집 사이트(입력 대비 %), 메타데이터(저장 문서)
    • 문서 단계별 통과 현황 막대: PDF 다운로드 / 텍스트 추출 / 요약 생성 (각 단계별 통과율)
  • EXCEPTIONS (PDF 누락과 사이트별 예외)
    • 요약 카드: PDF 다운로드 성공 / 다운로드 실패(실패율) / PDF 주소 없음
    • 실패 사이트 표 (실패 건수 상위 20개): 순위 · site_id · 메타 · PDF · 실패 · 실패율 · 진단(사유 라벨 및 상세). 작은 화면에서는 가로 스크롤됩니다.
  • DIAGNOSIS (누락 사유 진단) — 사유 라벨별 사이트 수, 진단 포함 사이트 수
  • RECOVERY (입력 항목 분류) — 회복 카테고리별 건수, 현재 입력 집계 기준 건수

사용 절차

  1. 브라우저 주소창에 /admin/collection-report 입력(또는 리포트 내 링크로 이동).
  2. STATUS 밴드로 단계별 통과율(어느 단계에서 손실이 큰지)을 파악.
  3. EXCEPTIONS 표에서 실패가 많은 사이트와 진단 사유를 확인.
  4. DIAGNOSIS/RECOVERY에서 사유 유형과 회복 가능성(수집 가능/수동/불가)을 판단.
  5. 회복 가능한 사이트는 크롤러 관리(3.7)에서 재실행을 검토.
집계할 데이터가 없으면 각 섹션에 "표시할 집계가 없습니다." 안내가 표시됩니다.
[스크린샷: 수집 보고서]

3.6 수집 현황 (사이트별 진행률) — /admin/status

목적
사이트별로 수집 → 다운로드 → 변환 → 요약 진행률을 표로 확인합니다.

주요 항목·컨트롤

  • 그룹 전환 탭 (우측 상단): 사이트 / 대륙 / 국가 / 범주 — 집계 단위를 바꿉니다.
  • 요약 통계 카드 5종: 활성 사이트 · 수집 문서 · 다운로드 완료(%) · 텍스트 변환(%) · AI 요약(%)
  • 진행률 표 — 컬럼:
    • 사이트(또는 그룹명), (그룹 모드 시) 사이트 수
    • 수집(총 문서 수)
    • 다운로드 / 변환 / 요약 — 각각 진행률 막대 + "N (P%)" 표시
    • 최근 (마지막 수집 일시)
    • 작업 — 사이트 모드는 보기(/search?site=...), 그룹 모드는 검색(대륙/국가/범주별 검색)
    • 사이트 모드에서는 사이트명 아래 site_id·국가·범주가 함께 표시

사용 절차

  1. 상단 네비에서 📈 수집 현황 클릭.
  2. 상단 카드로 전체 다운로드/변환/요약 진척을 확인.
  3. 사이트/대륙/국가/범주 탭으로 원하는 집계 단위 선택.
  4. 표에서 진행률 막대가 낮은(변환·요약이 뒤처진) 사이트를 식별.
  5. 보기/검색 링크로 해당 문서를 확인하거나, 필요 시 크롤러 관리에서 재수집.
문서가 하나도 없으면 노란 안내 박스에 첫 수집 명령 예시(python -m crawler.main crawl <site>)가 표시됩니다. DB 연결 실패 시 빨간 오류 박스가 표시됩니다.
[스크린샷: 수집 현황]

3.7 URL 크롤링 (Smart Find) — /smart-find

목적
URL 하나만 입력하면 그 페이지에서 다운로드 가능한 문서(PDF/HWP/XLSX 등) 를 자동으로 찾아냅니다. 패턴 매칭이 실패하면 LLM으로 페이지 구조를 분석합니다. 진행 상황은 실시간 스트리밍됩니다.

주요 항목·컨트롤

  • URL 입력창(필수)
  • 최대 페이지 (1~200, 기본 20)
  • 탐색 깊이 (0~5, 기본 3)
  • LLM Provider 드롭다운: GPT-5.4-mini / Gemini-2.5-flash
  • AI 분석 사용 체크박스(기본 켜짐) — 끄면 패턴 매칭만 사용
  • DB에 저장 체크박스(기본 꺼짐) — 켜면 발견 문서를 DB에 적재
  • 시작 / 중지 버튼
  • PROGRESS 패널 — 진행 로그 실시간 표시
  • 결과 섹션 — "N개 파일 발견", 스캔 페이지 수·상세 방문 수·fetch 방식 표시
    • DB 저장 시 "✓ DB에 N건 저장 · {siteId}" 배지
    • 경고가 있으면 "경고 N건" 펼치기
    • 파일 목록: 파일 형식 배지(색상 구분) + 제목 + 파일 URL + 새 탭 열기(↗)

사용 절차

  1. 상단 네비에서 🛰️ URL 크롤링 클릭.
  2. 대상 목록/게시판 URL을 입력.
  3. 최대 페이지·탐색 깊이·Provider를 필요에 맞게 조정.
  4. DB 적재까지 원하면 DB에 저장 체크.
  5. 시작 클릭 → PROGRESS에서 진행 확인(원하면 중지).
  6. 결과 목록에서 발견 파일을 확인하고 ↗로 원본 열기.
[스크린샷: URL 크롤링 (Smart Find)]

3.8 Auto-Add (전용 크롤러 자동 제작) — /auto-add

목적
URL 입력만으로 Codex(AI) 가 사이트 구조를 분석하고 전용 크롤러(Python 코드)를 자동 작성·검증합니다. 통상 10~15분이 소요됩니다.

주요 항목·컨트롤

  • URL 입력창(필수)
  • site_id (선택) — 비워두면 자동 생성
  • 시작 버튼 (진행 중에는 "동작중..." 스피너)
  • 진행 단계 카드 — 4단계 진척을 실시간 표시:
    1. 사이트 구조 분석
    2. 전용 크롤러 코드 작성
    3. 크롤러 검증
    4. 저장
    • 각 단계에 상태 아이콘(✓/⏳/✗)과 경과 시간 표시
    • 90초 이상 무응답 시 "응답이 없습니다" 경고
    • "개발자용 원본 로그" 펼치기로 원시 로그 확인
  • 성공 카드 (✅ 수집 준비 완료) — 검증 수집 건수, 크롤러 ID, 예시 제목, 실제 수집 시작 → 버튼(/crawler?site=...&from=auto-add)
  • 실패 카드 (❌ 수집 실패) — 경과 시간, (가능하면) 사람이 읽기 쉬운 오류 설명, 🔄 재시도 버튼, 원본 로그 보기

사용 절차

  1. 상단 네비에서 ✨ Auto-Add 클릭.
  2. 대상 URL을 입력(필요 시 site_id 지정).
  3. 시작 클릭 → 4단계 진행 카드로 상태 확인(10~15분).
  4. 성공하면 실제 수집 시작 → 를 눌러 크롤러 관리로 이동(검증 실행 권장).
  5. 실패하면 오류 설명 확인 후 재시도.
성공 후 크롤러 관리로 넘어가면 상단에 "Auto-Add에서 생성된 사이트입니다. 먼저 --limit 5 정도로 검증 실행을 권장합니다." 안내가 표시됩니다.
[스크린샷: Auto-Add]

3.9 크롤러 관리 — /crawler

목적
등록된 크롤러를 수동 실행하고, 실행 중인 작업(Job)과 진행 로그를 실시간으로 관리합니다.

주요 항목·컨트롤

  • 새 크롤링 실행 폼
    • 사이트 드롭다운 — 등록된 크롤러 목록에서 선택
    • doc_type (선택) — 사이트별 코드 등 자유 입력 필터
    • limit (선택) — 수집 건수 상한(비우면 무제한)
    • 증분 (incremental) 체크박스(기본 켜짐) — 새 문서만 수집
    • 실행 버튼 (Auto-Add에서 넘어온 경우 강조 색상 + 검증 실행 안내 배너)
  • 실행 중 Job 표 — Job ID · PID · 시작 시각 · 동작(로그 보기 / 중지). 5초마다 자동 갱신.
  • 로그 파일 영역
    • 좌측: 로그 파일 목록(파일명·크기·수정시각)
    • 우측: 선택한 로그의 실시간 스트리밍 뷰(터미널 스타일). 최근 500줄 유지, 자동 스크롤.
    • 스트림 닫기 버튼

사용 절차

  1. 상단 네비에서 ⚙️ 크롤러 관리 클릭.
  2. 사이트를 선택하고 필요 시 doc_type·limit 지정, 증분 여부 확인.
  3. 실행 클릭 → 새 Job이 생성되고 로그 스트림이 자동으로 열림.
  4. "실행 중 Job" 표에서 진행을 확인하고, 필요 시 로그 보기로 다른 Job 로그를 열거나 중지로 종료(확인 팝업).
  5. 과거 로그는 "로그 파일" 목록에서 선택해 확인.
신규(Auto-Add 생성) 사이트는 먼저 limit 5 정도로 검증 실행한 뒤 전체 수집을 진행하는 것을 권장합니다.
[스크린샷: 크롤러 관리]

4. 자주 하는 작업 (Task 기반)

4.1 특정 사이트의 수집 상태 보기

  1. 상단 네비 → 수집 현황(/admin/status).
  2. 그룹 탭을 사이트로 둠(기본값).
  3. 표에서 대상 사이트 행을 찾아 다운로드/변환/요약 막대 확인.
  4. 해당 행의 보기 클릭 → 그 사이트 문서가 검색 결과로 표시됨.
    • (대안) 대시보드 "최근 수집 사이트" 표의 문서 보기 사용.

4.2 미요약 문서 재요약

  1. 상단 네비 → 요약 결과(/admin/summary).
  2. 상태 드롭다운을 미요약으로 선택(필요 시 사이트도 선택) → 적용.
  3. 목록에서 대상 문서의 재요약 버튼 클릭.
  4. 버튼이 "요약 중…"으로 바뀌었다가 복귀하고 요약 본문이 채워지면 완료.
  5. 여러 건이면 각 행에서 반복. 오류 시 메시지 확인 후 재시도.

4.3 실패(오류) 문서·사이트 확인

  1. 브라우저 주소창에 /admin/collection-report 입력.
  2. EXCEPTIONS 표에서 실패 건수 상위 사이트와 진단 사유 확인.
  3. 단계별 손실은 STATUS 밴드(PDF/텍스트/요약 통과율)로 파악.
  4. 개별 문서의 원인 점검은 문서 상세(/admin/document/{seq_id})에서 pdf_downloaded·text_extracted·블롭 존재 여부(✓/✗)로 확인.
  5. 회복 가능 사이트는 크롤러 관리에서 재실행 검토.

4.4 새 URL 추가

A. 빠르게 다운로드 링크만 찾기 → URL 크롤링(Smart Find)

  1. 상단 네비 → URL 크롤링(/smart-find).
  2. URL 입력 → (선택) DB에 저장 체크 → 시작.
  3. 결과에서 발견 파일 확인, 필요 시 저장 배지로 적재 확인.

B. 사이트 전용 크롤러가 필요할 때 → Auto-Add → 크롤러 관리

  1. 상단 네비 → Auto-Add(/auto-add).
  2. URL 입력(선택 site_id) → 시작 → 4단계 완료까지 대기(10~15분).
  3. 성공 카드에서 실제 수집 시작 → 클릭 → 크롤러 관리로 이동.
  4. 크롤러 관리에서 limit 5 로 검증 실행 후, 이상 없으면 limit 없이(또는 증분) 본 수집 실행.

5. 참고

5.1 요약(AI) 엔진

  • 재처리(재요약)는 서버에서 python -m crawler.main summarize --doc-id {id} 를 실행합니다(타임아웃 90초).
  • 프로덕션 요약은 로컬 Ollama 모델(gemma4:26b 55% + qwen3:8b 45%, DB summary_model 실측)로 생성됐습니다. 코드(summarizer.py)의 기본값은 gpt-5.4-mini(환경변수 SUMMARIZER_MODEL)이나 프로덕션 요약엔 미사용입니다.
  • 요약 Provider 는 provider 인자 > 환경변수 LLM_PROVIDER > 기본 gpt 순으로 선택됩니다. Gemini 계열 모델은 gemini-2.5-flash 를 사용합니다.
  • 실제로 어떤 모델이 사용됐는지는 문서 상세의 summary_model 필드에서 확인할 수 있습니다.
참고(요약 엔진 정본): 프로덕션 요약 66,248건은 로컬 Ollama gemma4:26b(36,548·55%) + qwen3:8b(29,700·45%) 로 생성됨(DB summary_model 실측, 배치 스크립트 bulk_summarize_gemma.py). summarizer.py에는 OpenAI(gpt-5.4-mini)·Gemini 경로가 있으나 실제 요약에는 미사용. 계약(REQ-2026-001)의 OpenAI 대비 비용·온프레미스 이유로 로컬 모델로 구현함. 향후 OpenAI 폴백 도입은 계획.

별도로, URL 크롤링(Smart Find)의 구조 분석 LLM 은 화면에서 GPT-5.4-mini / Gemini-2.5-flash 중 선택하며, Auto-Add 의 크롤러 자동 제작은 Codex 를 사용합니다. (요약 엔진과는 별개입니다.)

5.2 데이터는 "읽기 위주"

  • 대시보드·수집 현황·수집 보고서·문서 검색·문서 상세는 모두 읽기 전용 집계/조회 화면입니다. 데이터를 직접 편집하는 기능은 없습니다.
  • 데이터는 저장소 루트의 libertree.db (SQLite)에 저장되며, DB가 없거나 연결에 실패하면 각 화면이 안내/오류 박스를 표시합니다(예상 경로 ../data/libertree.db).

5.3 재처리(재실행) 범위 — 무엇이 되고 무엇이 안 되는가

작업지원 위치지원 여부
재요약(summary)요약 결과 화면의 "재요약" 버튼지원
크롤링(수집) 수동 실행크롤러 관리지원(수집 실행)
신규 URL 문서 발견URL 크롤링(Smart Find)지원
신규 사이트 크롤러 자동 제작Auto-Add지원
텍스트 추출(재추출) 버튼—제공되지 않음
PDF 재다운로드 버튼—제공되지 않음(개별 재처리 UI 없음)
문서 상세 화면 내 재처리 버튼—제공되지 않음(검증 전용)
웹 UI에서 개별 문서 단위로 제공되는 재처리는 재요약뿐입니다. 텍스트추출 재처리 버튼은 존재하지 않습니다. 텍스트 추출/PDF 다운로드를 다시 하려면 크롤러(수집) 재실행 등 서버 측 작업이 필요합니다.

5.4 접속·인증 요약

  • 접속: http://localhost:3001 (헤더의 "port 3002" 라벨은 표시용이며 실제 포트가 아님)
  • 인증: HTTP Basic (ADMIN_USER / ADMIN_PASSWORD), realm Libertree Internal
