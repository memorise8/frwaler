이슈 1 · 3건 수집 후 나머지 자료 이어받기

FE의 ‘3건’은 건수 제한입니다. 정렬·중복 처리·재개 방식이 수집기마다 달라, 모든 사이트에서 최신 3건 또는 기준일 다음 3건이라는 동일한 의미를 보장하지 않았습니다.

수집기수정 전 / 확인된 문제이번 수정 및 검증
DOAJ기존 2만 건·신규 200건에서 신규 저장 3→0→0. 중복 문서가 제한에 포함됨.신규 저장만 계산. 알려진 문서 50건 조기 종료 해제. 3건 반복과 잔여 수집으로 신규 200건 저장 확인.

남은 개발

날짜순 신규 이어받기는 아직 미지원입니다. 실행 사이 원본 목록 변경·동률 날짜·지연 등록을 다루는 안정적인 재개 방식과 나머지 수집기 유형별 수정이 필요합니다. 무제한 설정은 내부 페이지·기간·시간 제한을 제거하지 않습니다.

이슈 2 · 검색 API 키 설정

항목기존 전달본이번 후보 코드
8개 키 보유공급사에 빈 값이 아닌 설정이 있음. 압축파일에는 실제 .env 없음.실제 값은 계속 별도 관리. 문서·번들에는 빈 예시만 포함.
Worker·BE 전달검색 키 전달 설정 누락.기본 Compose와 delivery/.env.example에 추가. 키 변경 시 두 서비스 재생성 필요.

진단인증 오류가 빈 결과처럼 나타날 수 있음.필수 키 누락·인증 실패·호출 제한·응답 오류·정상 빈 목록을 구분하도록 보완.
실제 인증미확인.여전히 미검증. ‘설정됨’은 API 인증 성공이 아님.

Algolia 7개, Azure Search 1개이며 GPT 키와 별개입니다. Cancer FR은 HTML 목록이 저장되지 않을 때 검색 키를 쓰는 보조 경로여서 선택 설정입니다. 나머지 7개는 해당 검색 경로에 필수입니다.
