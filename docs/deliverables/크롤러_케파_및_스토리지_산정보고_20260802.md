## 1. 핵심 요약 (Executive Summary)

| 지표 | 최종값 | 3,000만 대비 |
|---|--:|--:|
| **① 총 레코드 케파 (확정, exact)** | **6,018,334건** | **20.1%** |
| ① 최소 케파 (exact+하한) | 6,109,256건 | 20.4% |
| ② 그중 예상 PDF 문서 수 | 약 3,516,508건 | — |

**결론 3줄:**
1. **3,000만은 현재 소스(804개 크롤러)로는 도달 불가.** authoritative 상한이 **~600만(20%)** 에서 확정됨. 3,000만은 (a) 통계표·데이터셋 하위레코드까지 세거나, (b) 소스 목록을 대폭 확장해야만 성립.
2. **실제 구매 스토리지는 "PDF 건수" 기준 ~17.6 TB.** 텍스트 뉴스·통계 메타데이터는 용량 기여 ≈0. 현재 여유 3.6 TB → **약 14~18 TB 추가**면 현재 소스 전량 수집 가능. gdrive(1 PB) 오버플로 가능.
3. test.xlsx 1,995 URL 중 **수집률 91.4%** 로 향상(신규 크롤러 15개 추가). 나머지는 업체 확인 필요(아래 4장).

## 2. 왜 "3,000만"과 차이가 나는가 — 3층위 분리

"문서 3,000만"은 **무엇을 1건으로 세느냐**에 따라 달라진다.

- **층위① 총 레코드 케파 = 6,018,334** — 논문·데이터셋·통계표·보도자료 모두 1건씩. 소스의 검색 총량 API(numFound/totalElements/completeListSize/result.count/온페이지 카운트)로 측정.
- **층위② 전체 PDF 문서 ≈ 3,516,508** — 실제 다운로드 가능한 PDF만(사이트별 관측 PDF율 평균 57.7% 적용). **스토리지를 결정하는 수치.**
- **층위③ 논문형 PDF (참고)** — 데이터포털(e-stat 통계표)·CKAN 데이터셋·뉴스 제외 시 대략 2~2.5백만 수준 추정.

> **업체 확인 필요:** "3,000만"이 통계표/데이터셋 개별 레코드를 포함하는 개념인지 확인. 포함해도 현재 소스로는 미달 → **소스 확장이 사실상 전제.**

**권고:** 현재 소스 전량 수집 목표라면 **~20 TB급 증설**이면 충분. 3,000만 시나리오 대비는 100TB급이나 소스 확장 규모 확정이 선행.
